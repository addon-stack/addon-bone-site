Options creates an extension settings page that users open through the browser UI or from your extension.
Use it for interface preferences, feature settings, and managing optional access.
Write TypeScript code using the DOM directly or React; Addon Bone creates the HTML and registers it in the manifest.

Place your code in `options.ts` or `options.tsx`.
By default, Addon Bone configures the page to open in a separate tab; use `openInTab: false` to request an embedded settings interface if the browser supports it.
Options does not start with background: its code runs when the page loads.

## Quick Start

Create a settings page with simple text:

```ts file="../../../../code/entrypoints/options/options.ts" title="src/options.ts"
```

Add the file to your Addon Bone project, build the extension, and load it into the browser.
Open the browser's extension manager, find your extension, and open its settings.
In Chrome, select **Extension options** on the extension's details page.
You will see `Manage your extension preferences here.` and the tab title `Settings`.

Addon Bone creates `options.html`, writes its path to `options_ui.page`, and sets `options_ui.open_in_tab` to `true`.
The framework displays the `render` string as text and creates the container automatically.
This example needs no additional files, React, or permissions.

## Opening the Page

The browser shows a settings link after you load an extension with `options_ui` in its manifest.
The location of this link depends on the browser; you can also open the page from a popup or another extension context using `openOptionsPage` from `adnbn/browser`.

Add this file alongside `options.ts` from the Quick Start:

```ts file="../../../../code/entrypoints/options/open/popup.ts" title="src/popup.ts"
```

Build the extension and reload it.
Click the extension's toolbar button, then **Settings** in the popup: the browser opens the registered settings page.
This call needs no separate permission.
If your project already has a popup, move the button handler into it instead of creating a second file.

`openOptionsPage()` returns `Promise<void>` and uses the page registered in the manifest.
It respects `openInTab` and continues to work after you change the HTML filename through `as`.
Handle opening errors, for example when Options is excluded from the build.
See the [`runtime.openOptionsPage()` contract](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/runtime/openOptionsPage) for details.

<DocHeading level={3} id="options-open-mode" toc={false}>Tab or Embedded Interface</DocHeading>

`openInTab: true` opens settings in a regular tab.
Addon Bone writes this value even when you omit the option.
For an embedded interface, set it to `false`:

```ts file="../../../../code/entrypoints/options/embedded.options.ts" title="src/options.ts"
```

This version replaces the file from the Quick Start.
The manifest will contain `options_ui.open_in_tab: false`; the browser determines how to display the page:

| Browser | Behavior with `openInTab: false` |
| --- | --- |
| Chrome, Chromium, Edge | The page is embedded in the extension management UI |
| Firefox | The page opens in the Add-ons Manager |
| Opera | Settings still open in a separate tab |
| Safari on macOS and iOS | Settings still open in a separate tab |

Options uses `options_ui` in Manifest V2 and Manifest V3.
Safari supports this field since version 14 on macOS and version 15 on iOS.
See the [`options_ui` compatibility table](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/options_ui#browser_compatibility) for opening mode support.

Chrome's embedded page is not a separate tab: do not rely on `sender.tab` in messages sent from it.
Make the interface work in a narrow container; set a minimum content width in your styles if needed.
See [Chrome's embedded options behavior](https://developer.chrome.com/docs/extensions/develop/ui/options-page#consider_the_differences) for details.

- `options.{ts,tsx}` and `*.options.{ts,tsx}`;

<DocHeading level={3} id="options-selection" toc={false}>Selecting an Implementation</DocHeading>

The build includes one Options page.
If several matching files remain after filtering, Addon Bone selects the last one by priority: local files take precedence over plugin files, and among local files at the same level, the last file in path order wins.
Other candidates do not create additional pages or contribute their permissions or CSP.

For predictable selection, keep one implementation per build or separate variants with filters such as `includeBrowser` and `includeApp`.
See [Multi-App Structure](#multi-app-structure) for the rules that select the shared layer or app.

Enable **Compact interface**, close the page, and open it again: the checkbox stays checked.

`useStorage` reads the `settings.compact` key from local storage, subscribes to its changes, and updates the React component.
`defaultValue: false` provides the value to display until the key is written; it does not save the preference by itself.
Another extension context can read the same key using `storageLocal<boolean>("settings.compact")` from `adnbn/storage`.
`storage.local` stores data in the current browser profile and does not synchronize it across devices.

Both formats support the same options and build filters.
With named exports, declare options using `export const`; a bare `export default` maps to `render`.
Export an existing React component directly, as in `export default SettingsForm` in the example.
The **primary** badge identifies this mapping in the option descriptions.

For static text, pass a string directly, as in the [Quick Start](#quick-start).
Use a function when the content is created or computed as the page loads.
`render` is optional: if all markup is in an HTML template, setting `template` and the other page options is enough.

## Page Content

### Vanilla

Pass a DOM element, a non-empty string, or a number directly to `render`, or return it from a function.
This counter creates a button; Addon Bone places it inside a `main` container:

```ts file="../../../../code/entrypoints/options/counter.options.ts" title="src/options.ts"
```

Clicking the button increments the value and updates the button text.
Changing a variable alone does not redraw the DOM.

Strings are displayed as text: `"<strong>Hello</strong>"` does not become HTML.
For markup, create DOM elements, use an HTML template, or use React.
An empty string, `null`, `undefined`, and boolean values create neither content nor a container; the number `0` is displayed.

Vanilla calls `render(options)` when the page loads and uses its synchronous result.
To load data, return an element with initial content, then update it from a separate asynchronous function.
Handle errors in that function: Addon Bone does not wait for it to finish.

<DocHeading level={3} id="options-lifecycle" toc={false}>Loading and Closing</DocHeading>

Options code runs in an extension page context, separately from background.
The page exists while the browser keeps it open; closing or reloading it discards its in-memory state.
Save preferences when they change or when the user clicks a save button, rather than only when the page closes.

Each open copy of the page has its own DOM and React state.
Use storage and subscriptions for shared values, as shown in the [settings form](#defining-options).
Release a React component's subscriptions in its effect cleanup function.
`useStorage` manages its own subscription.
Delegate long-running background work to [Background](./background.mdx) or [Service](./service.mdx).

## Multi-App Structure

In a project with multiple apps, place the shared settings page in `src/shared` and each app's implementation in `src/apps/<app>`:

```tree file="../../../../code/entrypoints/options/multi-app.tree"
```

Enable multi-app mode in the project configuration:

```ts file="../../../../code/entrypoints/newtab/multi-app.config.ts" title="adnbn.config.ts"
```

If an app has Options files, Addon Bone uses that set instead of the shared set.
If the app has none, it uses the shared settings page.
There is no separate merge option: the build includes one selected page.
In a single-app project, use the regular `src` directory; a separate shared layer is not required.

The app or shared set is selected before filtering.
If an app file is found but then excluded, for example by `includeBrowser`, the shared page is not restored automatically.
Place variants in the selected set and configure filters so the implementation you need remains in the build.
Options from different files are not merged into one definition.

## Best Practices

- **Save data when the user acts.** Closing the page should not be the only time you write preferences.
- **Show loading and errors.** Disable changes until a preference has loaded, and report failed writes.
- **Use storage for shared values.** React state and page variables disappear when the page closes; preferences need to remain available to other extension contexts.
- **Open settings through `openOptionsPage`.** This preserves the opening mode and avoids tying code to an HTML filename.
- **Test both interface modes.** With `openInTab: false`, test sizing and behavior in the extension manager; account for browsers that still open a tab.
- **Keep one matching implementation.** Use filters for browser and app variants.

## Debugging

1. **Options is missing from the build.** Check the filename, location, filters, and selected app or shared set. Verify that the final manifest contains `options_ui.page` and that the referenced HTML exists.
2. **The settings link is missing or opening fails.** Reload the extension after building. Check `options_ui` and the error from `openOptionsPage()`: if Options is excluded, there is no page to open.
3. **Settings open in a separate tab with `openInTab: false`.** Check `options_ui.open_in_tab`. This is browser behavior in Opera and Safari; in Chrome and Firefox, make sure you are testing the reloaded extension.
4. **A different implementation opens.** Check the matching Options files and the manifest path. Remove extra candidates or separate them with filters.
5. **The page opens without content.** Check the `render` result and the page's own console. Vanilla needs a DOM element, a non-empty string, or a number; React needs a `.tsx` / `.jsx` file and installed dependencies.
6. **HTML tags appear as text.** A `render` string is displayed literally. Create DOM elements or use JSX or a template for markup.
7. **A preference resets after closing.** Verify that the value is written to storage rather than only to a variable or React state. Check the `storage` permission in the manifest and any read or write errors.
8. **CSS or an additional script does not load.** Check that the file is in the build and verify the path in `links`, `scripts`, or `tags`. Put ready-to-use resources in `src/public`; check the `template` path relative to the entrypoint.
9. **A browser API or server request is blocked.** Check the selected Options page's permissions in the final manifest, granted optional access, and CSP. Reload the extension after changing permissions.
