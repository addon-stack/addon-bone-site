Popup creates a small window that users open by clicking your extension's button in the browser.
Use it for quick actions on the current tab, checking the extension's status, and controlling its features.

Place your code in `popup.ts` or `popup.tsx`.
You can work with the DOM directly or use React; Addon Bone creates the HTML, connects the page's code, and assigns the Popup to the extension button.

## Quick Start

Create a Popup with simple text that opens when the user clicks the extension button:

```ts file="../../../../code/entrypoints/popup/popup.ts" title="src/popup.ts"
```

Add the file to your Addon Bone project, build the extension, and load it into the browser.
Click the extension's icon in the toolbar or extensions menu; pin it to the toolbar if needed.
The window displays `Your extension is ready.`, and the button's tooltip reads `Open quick actions`.
`title` sets the HTML document title; `tooltip` sets the text shown when the user hovers over the extension button.

Addon Bone creates `popup.html` and writes its path to `action.default_popup` for Manifest V3 or `browser_action.default_popup` for Manifest V2.
The framework displays the `render` string as text and creates the container automatically.
This example needs no additional files, React, or permissions.

## Opening and Closing

The browser loads the Popup when it opens and destroys its document when it closes.
Variables, DOM elements, and React state are created again the next time it opens.
Save data you need in extension storage; move long-running work to [Background](./background.mdx) or [Service](./service.mdx).

Clicking outside the Popup closes the window.
Chrome cannot keep it open after it loses focus; use a separate [extension page](./page.mdx) or [Sidebar](./sidebar.mdx) for longer interactions.
See [the Popup lifecycle in Chrome](https://developer.chrome.com/docs/extensions/develop/ui/add-popup) for details.

When the button has a Popup assigned, the `action.onClicked` event does not fire.
Put UI actions in its event handlers and initial data loading in the page's code or React effects.
This also applies to `browserAction.onClicked` in Manifest V2.
See [extension button behavior](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/user_interface/Toolbar_button#specifying_the_browser_action).

The window size depends on its content and the browser's limits.
Chrome automatically sizes the Popup between 25 × 25 and 800 × 600 pixels.
Set its width, spacing, and wrapping of long text through styles; `definePopup` has no separate size option.
See the [styles example](#styles-and-modules) and [Chrome's Action API Popup documentation](https://developer.chrome.com/docs/extensions/reference/api/action#popup) for the browser limits.

An `account.popup/` directory with an `index.tsx` file declares a Popup with the alias `account`.
You can use a single `account.popup.tsx` file instead.
Choose a directory when you want to keep this Popup's components, styles, and assets together.

These paths are supported for TypeScript; `{ts,tsx}` represents two possible extensions:

- `popup.{ts,tsx}` and `*.popup.{ts,tsx}`;
- `popup/index.{ts,tsx}` and `*.popup/index.{ts,tsx}`;
- `popups/popup.{ts,tsx}` and `popups/*.popup.{ts,tsx}`;
- `popups/popup/index.{ts,tsx}` and `popups/*.popup/index.{ts,tsx}`.

Use `.ts` for Vanilla and `.tsx` for React.
For JavaScript, use the same paths with `.js` or `.jsx`: `.js` selects Vanilla, and `.jsx` selects React.
Discovery also recognizes `.vue` and `.svelte`, but there are currently no built-in View adapters for these formats; use Vanilla or React for working examples.

:::warning Discovery Scope
If Addon Bone finds entrypoints in `popups/`, it uses that directory instead of Popup files at the top level of the same source scope.
For example, when `popups/account.popup/index.tsx` exists, a `popup.ts` file alongside the directory is excluded from the build.
This rule applies separately to the shared layer and each app, before filters: excluding a discovered file does not restart discovery at the top level.
:::

<DocHeading level={3} id="popup-selection" toc={false}>Selecting an Implementation</DocHeading>

With `multiplePopup: false`, the default, the build includes one Popup.
After applying filters, Addon Bone selects the last file by priority: app files take precedence over the shared layer and plugins, and among local files at the same level, the last file in path order wins.
Other candidates do not generate HTML, appear in `getPopups()`, or contribute permissions or CSP.

For a single implementation, keep one matching file or separate variants with filters such as `includeBrowser` and `includeApp`.
To switch between several built interfaces, use [multiple Popups](#multiple-popups).

This version replaces `popup.ts` from the Quick Start.
Build the extension, reload it, open a regular web page, and click the extension button.
Click **Read current tab** in the Popup: while the request runs, the button displays `Loading…` and is disabled, then the tab title or an error message appears below it.
After reopening the Popup, click the button again: the result is stored only in component state.

[`useActionState`](https://react.dev/reference/react/useActionState) stores the operation's result in `message` and returns `isPending` while the request runs.
The handler returns the title on success or a message on error.
With `action={load}`, React runs the handler when the form is submitted and tracks its execution; no separate `startTransition` call is needed.

`activeTab` does not grant permanent access to all sites or remove restrictions on internal browser pages.
Navigating to another site revokes temporary access; clicking the extension button grants it again.
See [what `activeTab` allows and when it applies](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) for details.

Both formats support the same options and build filters.
With named exports, declare options through `export const`; a bare `export default` maps to `render`.
Export an existing React component directly, as in `export default CurrentTab` in the example.
The **primary** badge marks this mapping in the option descriptions.

For constant text, pass a string directly, as in [Quick Start](#quick-start).
Use a function when the content is created or computed as the page loads.
`render` is optional: if all markup is in the HTML template, setting `template` and the other page options is enough.

## Page Content

<ViewRendering />

### Vanilla

Pass a DOM element, a non-empty string, or a number directly to `render`, or return it from a function.
This counter creates a button; Addon Bone places it inside a `main` container:

```ts file="../../../../code/entrypoints/popup/counter.popup.ts" title="src/popup.ts"
```

Clicking the button increments the value and updates the button text.
Changing the variable alone does not update the DOM.
Closing the window resets the value: this example keeps the counter only in the Popup's memory.

A string is displayed as text: `"<strong>Hello</strong>"` does not become HTML.
For markup, create DOM elements, use an HTML template, or use React.
An empty string, `null`, `undefined`, and booleans create neither content nor a container; the number `0` is displayed.

Vanilla calls `render(options)` when the page loads and uses its synchronous result.
To load data, return an element with initial content, then update it from a separate asynchronous function.
Handle errors in that function: Addon Bone does not wait for it to finish.

[`useActionState`](https://react.dev/reference/react/useActionState) stores the success or error message and returns `isPending` while switching is in progress.
During this time, the buttons are disabled and the form shows `Applying…`.
With `formAction={() => apply(alias)}`, React runs the handler in an Action context and tracks the operation; no separate `startTransition` call is needed.

To restore the selection after restarting the browser, save the alias in storage and apply it from [Background](./background.mdx) at startup.
To navigate between screens in an already open Popup, update React state or use routing within its page.

<DocHeading level={3} id="popup-apply" toc={true}>Initial Popup</DocHeading>

With `multiplePopup: true`, the first built Popup with `apply: true` or no `apply` option becomes the initial Popup.
The order starts with plugin files, followed by the shared layer and app; local files at the same level follow path order.
For an explicit choice, set `apply: false` on the other variants, as in the example.
With `multiplePopup: false`, Addon Bone first selects a single file by the [priority rules](#popup-selection), then checks its `apply` option.

`apply: false` does not exclude the file from the build: its HTML and alias remain available, and its permissions and CSP are included.
If none of the built Popups is applied, Addon Bone does not set `default_popup`.
This set of Popups alone also does not add an `action` / `browser_action` field; the field may come from the `action` configuration or an `_execute_action` command.
To assign a Popup only from code, declare `action: {}` in the project configuration and leave `apply: false` on all variants.

<DocHeading level={3} id="popup-runtime" toc={true}>Switching at Runtime</DocHeading>

`getPopups()` from `adnbn` returns a `PopupMap`: a `Map<PopupAlias, PopupMapEntry>` containing the aliases of built Popups and the data needed to switch between them.
The `PopupMap`, `PopupAlias`, and `PopupMapEntry` types are also available from `adnbn`.
`PopupMapEntry` has three optional fields:

- `path?: string` — the HTML path inside the extension;
- `tooltip?: string` — the original tooltip text or localization key, such as `@popup.account`;
- `icon?: string` — the icon group name.

The document title `title` is not part of this entry: it remains a page option and is available in `PopupProps`.
`getPopups()` does not translate `tooltip`; if a menu needs labels for the variants, define them separately from the button's tooltip.
Aliases depend on the filename or `as`; see the table in [Build Output](#build-output).
In `.adnbn/popup.d.ts`, Addon Bone augments `PopupAliasRegistry` with variant names for TypeScript suggestions.

`changePopup(alias, tab?)` returns `Promise<void>`.
Call it from background or an extension page.
Without the second argument, it changes the Popup for the button globally; pass a tab ID or tab object to set an override for that tab.
The tab override takes precedence over the global value and resets when the tab closes.
See [per-tab action settings](https://developer.chrome.com/docs/extensions/reference/api/action#per-tab_state) for details.

The call changes what opens the next time the button is clicked; it does not replace an already open document or open a new window.
If the selected Popup has `tooltip` or `icon` set, `changePopup` also updates the corresponding button properties.
An omitted field preserves the button's current value; configuration values are not restored automatically.
The HTML document title comes from the selected Popup's `title` when it loads.

Handle call errors: the alias may be missing from the current build, or the browser may reject the change.
The Popup path, tooltip, and icon are changed in sequence.
If updating the tooltip or icon fails, changes already made remain in place.

To open the currently assigned Popup programmatically, use `openActionPopup()` from `adnbn/browser`.
This function returns `Promise<void>` and optionally accepts a window ID.
Support depends on the browser and version: in Chrome Manifest V3, the method is available to regular extensions from Chrome 127; versions 118–126 allow it only for extensions installed by policy.
Check compatibility with your target browser and handle opening failures.
See the [Chrome `action.openPopup()` contract](https://developer.chrome.com/docs/extensions/reference/api/action#method-openPopup) and [browser compatibility](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/action/openPopup#browser_compatibility).

<Details title="Empty Tooltip Value">

An empty string, `tooltip: ""`, differs from an omitted option: when switching, `changePopup` passes an empty value to the browser rather than preserving the current tooltip.

An empty value does not guarantee a hidden tooltip: the browser controls how it is displayed and may show the extension's name.
See [how the browser handles an empty value](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/action/setTitle) for details.

## Options

`PopupDefinition` options apply to an individual Popup: they set its content, HTML configuration, initial assignment to the button, and conditions for inclusion in the build. `PopupConfig` groups the button-specific fields.
Set `multiplePopup` and `mergePopup` in the project configuration, outside `definePopup`.

<DocHeading level={3} id="popup-action-options" toc={false}>Extension Button</DocHeading>

<EntrypointSpec name="apply" type="boolean" manifest>
    Determines whether this Popup can be the initial one for the extension button.
    If omitted, Addon Bone uses <code>true</code>.
    With <code>false</code>, the built Popup remains available through <code>changePopup</code> but is not assigned in the manifest.
    Selection among several files is described in the <a href="#popup-apply">Initial Popup section</a>.
</EntrypointSpec>

<EntrypointSpec name="icon" type="IconName" manifest>
    Accepts an <code>IconName</code>: the name of an icon group for the extension button, such as <code>icon: "toolbar"</code>.
    This is a group name from <code>src/icons</code>, rather than a path to an individual image.
    For example, <code>toolbar-16.png</code> and <code>toolbar-32.png</code> form a <code>toolbar</code> group with two sizes.
    For the initial Popup, omitting the option uses <code>action.icon</code> from the configuration, then the general <code>icon</code>.
    When switching through <code>changePopup</code>, a specified group replaces the button's icon; an omitted option preserves the current icon.
    To change only the icon, use <code>changeActionIcon()</code>.
</EntrypointSpec>

<EntrypointSpec name="tooltip" type="string" manifest>
    Sets the tooltip shown when the user hovers over the extension button.
    Accepts plain text or a localization key, such as <code>tooltip: "@popup.account"</code>.
    For the initial Popup, Addon Bone writes the value to <code>manifest.json</code>:
    the <code>action.default_title</code> field for Manifest V3 or <code>browser_action.default_title</code> for Manifest V2.
    The generated fields are shown in <a href="#build-output">Build Output</a>.
    If omitted, the tooltip comes from <code>action.title</code> in the project configuration, then from the extension's name.
    When switching through <code>changePopup</code>, a specified <code>tooltip</code> replaces the button's tooltip;
    an omitted option preserves the current tooltip.
    An empty string, <code>""</code>, sets the value explicitly rather than preserving the previous tooltip.
    The translation example and empty value behavior are described in the <a href="#popup-localization">localization section</a>.
</EntrypointSpec>

## Multi-App Structure

In a project with several apps, place the shared Popup in `src/shared` and an app-specific implementation in `src/apps/<app>`:

```tree file="../../../../code/entrypoints/popup/multi-app.tree"
```

Enable multi-app mode in the project configuration:

```ts file="../../../../code/entrypoints/newtab/multi-app.config.ts" title="adnbn.config.ts"
```

With `mergePopup: false`, the default, app files replace the shared set.
If an app has no Popup files of its own, Addon Bone uses the shared set.
With `mergePopup: true`, it collects candidates from both layers.
Options from different files are not merged into one definition.

`mergePopup` controls the set of candidates, while `multiplePopup` controls the number of generated pages.
With `multiplePopup: false`, one Popup is still selected after merging and filtering; the app implementation takes precedence over the shared layer.
With `multiplePopup: true`, matching files become separate pages; choose the initial one through `apply`.
For shared and app variants that need to be included in the same build, use distinct names or `as` values.
In a single-app project, use the regular `src`; a separate shared layer is not required.

The app or shared set is selected before filters are applied.
With merging disabled, discovering an app file and then excluding it does not automatically restore the shared implementation.
Place variants in the selected set and configure filters so the required implementation remains in the build.

## Best Practices

- **Account for the window's short lifetime.** Save data when the user acts and move long-running tasks to the background context.
- **Start with a ready interface or loading state.** Load data asynchronously after synchronous `render` and display errors.
- **Keep the interface compact.** Set a width and wrap long text; check sizes in your target browsers.
- **Request access for the task.** Use `activeTab` for tab data after a button click when permanent access is unnecessary.
- **Choose the initial Popup explicitly.** With several interfaces, enable `multiplePopup` and leave `apply: true` only on the intended variant.
- **Switch by alias.** Use `changePopup` to avoid depending on the HTML path; remember that the change is visible the next time the Popup opens.

## Debugging

1. **Popup is missing from the build.** Check the filename, location, filters, and selected app or shared set. When `popups/` contains entrypoint files, the top level is not used. Confirm that the required HTML exists in the build.
2. **Clicking the button does not open a window.** Check `action.default_popup` or `browser_action.default_popup`, the `apply` value, and the HTML path. Reload the extension after building; check whether other code has changed the Popup for the active tab.
3. **A different interface opens, or an alias is missing.** Check `multiplePopup`, filters, and the contents of `getPopups()`. With one Popup, the last candidate by priority is selected; with several, the first candidate whose `apply` allows it becomes the initial Popup.
4. **The extension button click handler does not run.** When a Popup is assigned, the browser does not send `action.onClicked` / `browserAction.onClicked`. Move the action into a handler inside the Popup, or remove the Popup assignment if you only need the extension button's handler.
5. **The window opens without content.** Check the `render` result and the Popup's own console. Vanilla needs a DOM element, a non-empty string, or a number; React needs a `.tsx` / `.jsx` file and installed dependencies.
6. **HTML tags appear as text.** A string from `render` is displayed literally. Create DOM elements, or use JSX or a template for markup.
7. **State resets after closing.** Each opening creates a new document. Check that data you need is written to storage rather than only to a variable or React state.
8. **Switching did not change the open window.** Close and reopen the Popup. Check the second argument to `changePopup`: a per-tab setting can override the global value.
9. **The tab URL is missing, or a browser API is blocked.** Check the built Popup's permissions in the generated manifest, temporary `activeTab` access, and restrictions on the current page. Reload the extension after changing permissions.
10. **CSS, a script, or an asset does not load.** Check that the file exists in the build, its path in `links`, `scripts`, or `tags`, and CSP. Put ready-to-use resources in `src/public`; check the `template` path relative to the entrypoint.
11. **The button's tooltip did not change or is empty.** Set `tooltip` rather than `title`: without `tooltip`, switching preserves the previous tooltip. For a localization key, check the message in the built `_locales` and the browser's language; an empty translation or one the browser cannot find is passed as an empty string when switching.

Open developer tools for the Popup window itself, for example through **Inspect** in its context menu.
The background console belongs to a different context and does not show all UI errors.
