Offscreen lets you work with the DOM in a hidden extension document.
Use it when background code needs to parse HTML, process an image with canvas, or use an API that requires `window` and `document`, without opening a visible page.

Define the operations as methods of an object or class and call them through `getOffscreen(name)`.
Addon Bone creates the hidden document when you call a method and provides TypeScript hints for arguments and results.
Offscreen works in Manifest V3, Manifest V2, and Firefox builds, including environments without a native Offscreen API.
Addon Bone chooses how to create the document; the API definition and method calls stay the same.

Return the API with the operations you need from `init`.
If these operations need elements in the document, add `render`: Addon Bone creates a container and mounts the returned content inside it.
The document stays hidden.

## When to Use Offscreen

Choose Offscreen for work that needs a document but no visible interface:

- Parse HTML with `DOMParser` and return the data you need.
- Process images with `Image` and canvas: resize, crop, or convert their format.
- Work with the clipboard through the browser's available Clipboard APIs.
- Embed an iframe when you need to read or change its DOM and the browser allows that access.
- Use other Web APIs that need `window` or `document`.

Keep querying tabs, capturing screenshots, saving files, and managing permissions in background.

Offscreen does not bypass site access rules, iframe restrictions, or the requirements of a Web API.
For example, loading a remote image may require permission for its host, while camera access depends on browser support and user consent.
The Addon Bone API format stays the same across builds, but you need to check these browser requirements for your task.

Keep files directly in `src` or group them in `offscreens/`.
The following paths are supported for TypeScript and React; `{ts,tsx}` represents the two file extensions:

- `offscreen.{ts,tsx}` and `*.offscreen.{ts,tsx}`;
- `offscreen/index.{ts,tsx}` and `*.offscreen/index.{ts,tsx}`;
- `offscreens/offscreen.{ts,tsx}` and `offscreens/*.offscreen.{ts,tsx}`;
- `offscreens/offscreen/index.{ts,tsx}` and `offscreens/*.offscreen/index.{ts,tsx}`.

Use `.ts` for Vanilla and `.tsx` for React.
For JavaScript, use the same paths with `.js` or `.jsx`: `.js` selects Vanilla, and `.jsx` selects React.

:::warning Discovery scope
If Addon Bone finds entrypoints in `offscreens/`, it uses that folder instead of Offscreen files at the top level of the same source scope.
For example, if `offscreens/parser.offscreen.ts` exists, an `images.offscreen.ts` file next to the folder is not included in the build.
Move all Offscreen files in that scope into `offscreens/` when you choose this grouping.

In a multi-app project, the rule applies separately to the shared layer and the current app.
The folder is selected before filters are checked: excluding files by browser or manifest version does not make discovery return to the top level.
:::

<DocHeading level={3} id="offscreen-names" toc={false}>Offscreen Names</DocHeading>

| File | Default name |
| --- | --- |
| `offscreen.ts` or `offscreen/index.ts` | `offscreen` |
| `images.offscreen.ts` or `images.offscreen/index.ts` | `images` |
| `offscreens/images.offscreen.ts` | `images` |

Use this name in `getOffscreen(name)`.
Set `name` explicitly if it needs to stay the same after a file is renamed.
An explicit name starts with a letter, `_`, or `$`; the remaining characters can be letters, digits, `_`, or `$`.
Unicode letters are also allowed.
A name derived from a file can contain other characters: for example, `image-tools.offscreen.ts` gives the name `image-tools`, even though a hyphen is not allowed in an explicit `name`.

:::warning Duplicate names
If several local Offscreen entrypoints get the name `parser`, Addon Bone registers them as `parser`, `parser1`, and `parser2`.
One implementation does not replace another.
Choose unique names for stable calls.
If one API has several implementations, set filters so that exactly one is included in each build.
:::

Addon Bone processes Offscreen entrypoints from plugins first, then the shared layer and the current app.
Within each level, files are ordered by path.
This order affects naming; documents start when their APIs are called.

<DocHeading level={3} id="offscreen-direct-access" toc={false}>Access Inside the Hidden Document</DocHeading>

If code already runs inside Offscreen, use the instance passed to `main`.

## Generated Contracts

During the build, Addon Bone reads the API shape returned from `init` and creates types for `getOffscreen`.
TypeScript provides hints for names, methods, arguments, and results.
For the proxy, synchronous results become Promises.

The contract includes public methods and properties, nested objects, and inherited public class methods.
Members marked `private`, `protected`, or `static`, and names starting with `_`, are excluded.

The caller gets `title()`, but not `_parse()`.
The `_` prefix hides a method from the generated types; the method remains available on the actual instance.
The `Document` returned by `_parse()` does not pass through the proxy: the public method returns a string.

## Runtime and Concurrency Model

On the first method call, Addon Bone creates the hidden document and registers its API.
Subsequent calls use the same instance while the document exists.
Field state is preserved between these calls but is lost when the document closes.

Addon Bone calls `init`, registers the API, waits for `main` to finish, and then runs `render` if it is defined.
Elements created in `render` are not yet available in `init` and `main`.
If an API method uses document content, wait for the required resource inside that method, such as an iframe's `load` event.

<DocHeading level={3} id="offscreen-native-lifecycle" toc={false}>Chrome with Manifest V3</DocHeading>

In Chrome with Manifest V3, one Offscreen document can be open at a time per extension profile.
The regular and incognito profiles can have separate documents in split mode.
See the [Offscreen lifecycle in Chrome](https://developer.chrome.com/docs/extensions/reference/api/offscreen#concepts_and_usage).

When the API of an already open document is called, Addon Bone reuses it.
Several calls to the same Offscreen can run concurrently: Addon Bone does not wait for one method to finish before starting another.
If methods change a shared resource, such as one canvas, coordinate access inside the API or create a separate resource for each call, as in the Quick Start.

When another Offscreen is needed, Addon Bone waits for current proxy calls to finish, closes the previous document, and creates the new one.
Returning to the previous API creates its instance again.
Long-running work started by a method but not included in its returned Promise does not prevent this switch.
Wait for the operation inside the method if it must finish before switching documents.

You do not need to create, close, or switch documents manually for normal calls.
A call also does not mean that the document closes immediately after returning a result.
For `AudioPlayback`, Chrome closes the document after 30 seconds without audio playback; other reasons do not set this timer.
See the [Offscreen creation reasons](https://developer.chrome.com/docs/extensions/reference/api/offscreen#reasons).

<div id="write-once-across-runtimes" />

<DocHeading level={3} id="offscreen-compatible-lifecycle" toc={false}>Manifest V2 and Firefox</DocHeading>

In Manifest V2 and Firefox, Addon Bone creates hidden documents in the background page through its compatibility mechanism.
Different Offscreen documents can exist at the same time, so Chrome's one-document limit does not apply to these builds.
The framework waits for each document to be ready before sending a request.

Define one API for common DOM tasks and call it through the same `getOffscreen(name)`.
You do not need separate implementations by manifest version just to access `document`.
Use build filters if the operation itself depends on browser support for a particular API.

Keep long-lived data outside the Offscreen instance.
The document can be recreated when switching, reloading the extension, or restarting the background page.
Its presence also does not mean that background will run continuously.

In the object, `MessageSenderAware` provides hints for `$sender` through the `this` parameter.
This TypeScript parameter does not become a call argument in the generated contract.

In the class, `declare` describes a field for TypeScript without creating it on the instance.

Pass any information about the original request separately if the operation needs it.

Do not store `$sender` in an instance field: concurrent calls have different senders.
Direct access from `main` or through `adnbn/offscreen` does not add sender context.

## Hidden Document Content

Use `render` when an Offscreen operation needs an element mounted in the document.
Addon Bone creates a container, adds it at the start of `document.body`, and mounts the content inside it.
The document stays hidden; you do not need to add the container to `body` yourself.

`render` returns content synchronously, without a Promise.
Run asynchronous work in API methods or in the code that manages the mounted content.
If `render` is omitted, Addon Bone does not create a container for it; the HTML template's markup remains in the document.

### Vanilla

Use `.ts` or `.js` to work with the DOM directly.
Pass a DOM element, a non-empty string, a number, or a function that returns one of these values to `render`.
Strings are displayed as text: create elements or use a [custom template](#html-template) for HTML markup.
An empty string, `null`, `undefined`, and booleans create neither content nor a container; the number `0` is displayed.

Settings from included Offscreen entrypoints are combined with other extension pages' CSP into a shared manifest policy, even if the hidden document has not been created yet.
Sandbox has a separate policy.
In Chrome Manifest V3, JavaScript must be bundled with the extension: `scripts` does not allow remote code, inline handlers, or `eval`.
See the [CSP rules for extension pages](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy).

## Multi-App Structure

In a project with several apps, place shared Offscreen files in `src/shared` and app-specific files in `src/apps/<app>`.
In a single-app project, use the regular `src` directory; no separate shared layer is required.


Enable `mergeOffscreen` to let an app use both the shared `parser` and its own `images`:

```ts file="../../../../code/entrypoints/offscreen/multi-app.config.ts" title="adnbn.config.ts"
```

<div id="multi-app-merge" />

`mergeOffscreen` defaults to `false`:

- When `true`, Offscreen files from the shared layer and the current app are included together.
- When `false`, if the app has Offscreen files, their entire set is used instead of the shared set.
- If the app has no Offscreen files, the shared set is used regardless of `mergeOffscreen`.

Addon Bone first selects app or shared files, then applies entrypoint filters.
If an app file is found but later excluded, for example by `includeBrowser`, shared files are not brought back automatically.
Use `mergeOffscreen: true` if shared APIs are needed alongside the app's APIs.

Local Offscreen entrypoints with duplicate names get numeric suffixes under the normal naming rules.
Options from different files are not merged into one definition.

## Best Practices

<div id="best-practices-critical" />
<div id="best-practices-recommended" />

- **Keep DOM work in Offscreen.** Fetch data through extension APIs and save the result in background.
- **Choose reasons for the operation.** Set suitable `reasons` and a specific `justification` for a working extension.
- **Return JSON-compatible data.** For example, return image dimensions as an object with numbers; keep `Image`, canvas, and `Blob` inside the document.
- **Finish work before returning the result.** If an operation continues outside the returned Promise, switching documents may interrupt it.
- **Account for concurrent calls.** Create separate resources per request or coordinate access to shared resources inside the API.
- **Keep long-lived data outside the instance.** Switching documents in Chrome with Manifest V3 creates the instance's state again.
- **Use unique names.** Automatic suffixes depend on the set of included files.

## Debugging

- **The document is missing from the build.** Check the filename and location, filters, and `mergeOffscreen`. If files exist in `offscreens/`, move the required Offscreen there as well.
- **`getOffscreen` does not accept the name.** Find it in `.adnbn/offscreen.d.ts`. If a numeric suffix was added, set a unique name or exclude the extra implementation with filters.
- **A background call reports an invalid context.** Check the import: use `adnbn`, not `adnbn/offscreen`. The latter is for direct access inside the hidden document.
- **A method fails.** Handle the rejected Promise in the caller and open DevTools for the hidden document where the operation runs. Check resource loading, CSP, and JSON compatibility of arguments and results.
- **The browser blocks an operation.** Check permissions in the generated manifest and CSP, and make sure any optional access has been granted. Reload the extension after changing permissions. If an extension API is unavailable in a native Chrome Offscreen document, run the operation in Service or Background: adding a permission will not make that API available.
- **Method hints are missing.** Check `.adnbn/offscreen.d.ts` and whether the declarations are included in the project's TypeScript configuration. Make sure the generator can see the shape returned from `init`; refine the types with annotations or JSDoc if needed.
- **A call to another Offscreen waits a long time.** In Chrome with Manifest V3, check whether previous proxy calls have finished. A long operation keeps the active document until it returns a result.
- **State disappears after another call.** Check whether the hidden document was switched. Store data that needs to survive its closure outside the instance.
