Page creates a separate extension page: help, a dashboard, or another interface that needs its own tab or window.
You write the page in TypeScript, working with the DOM directly or using React.
Addon Bone creates HTML and connects the required scripts.

Place your code in `*.page.ts` or `*.page.tsx` and get the page URL through `getPageUrl(name)`.
For JavaScript, the same names are available with `.js` and `.jsx` extensions.
Open this URL in a new tab or use it in a link inside the extension.
Your code decides when to open the page.

## Quick Start

Create a help page and open it with a keyboard shortcut.
Page works well for help that the user can leave open in a separate tab.
The command opens the page, and Page provides its content.

<Tabs>
    <Tab label="Page source">
```ts file="../../../../code/entrypoints/page/help.page.ts" title="src/help.page.ts"
```
    </Tab>
    <Tab label="Command source">
```ts file="../../../../code/entrypoints/page/open-help.command.ts" title="src/open-help.command.ts"
```
    </Tab>

Add these files to an Addon Bone project, build the extension, and load it in your browser.
Press `Ctrl+Shift+Y` to open a tab titled `Help` with a welcome message.
On macOS, the browser converts `Ctrl` to `Command`.
If the shortcut is already in use, choose another in the browser's command settings, as described in the [Command guide](./command#keyboard-shortcuts).

Addon Bone derives the name `help` from the filename.
`getPageUrl("help")` returns the generated page's URL, and `createTab` opens it.
`render` contains the text the framework places in the container.

This example needs no additional files, React, or permissions.
Opening a new tab does not require `tabs`: this permission is needed to read protected tab information, such as titles.
See the [Tabs API permissions](https://developer.chrome.com/docs/extensions/reference/api/tabs#permissions).

## File Structure

Addon Bone discovers pages by file and directory names.
Each included Page gets its own HTML; you do not need to list these pages in the manifest manually.

The following paths are supported for TypeScript and React; `{ts,tsx}` represents the two file extensions:

- `page.{ts,tsx}` and `*.page.{ts,tsx}`;
- `page/index.{ts,tsx}` and `*.page/index.{ts,tsx}`;
- `pages/page.{ts,tsx}` and `pages/*.page.{ts,tsx}`;
- `pages/page/index.{ts,tsx}` and `pages/*.page/index.{ts,tsx}`.

Use `.ts` for Vanilla and `.tsx` for React.
For JavaScript, use the same paths with `.js` or `.jsx`: `.js` selects Vanilla, and `.jsx` selects React.

:::warning Discovery scope
If Addon Bone finds pages in `pages/`, it uses them instead of Page files at the top level of the same source scope.
Move all pages in that scope to `pages/` if you choose grouping.

In a multi-app project, this rule applies separately to the shared layer and the current app, before build filters are checked.
If a page in `pages/` is then excluded by browser or manifest version, discovery does not fall back to the top level.
:::

| --- | --- | --- |
| `page.ts` or `page/index.ts` | `page` | `page.html` |
| `help.page.ts` or `help.page/index.ts` | `help` | `help.html` |
| `pages/help.page.ts` | `help` | `help.html` |

`name` sets the name for `getPageUrl`, and `as` sets the HTML filename.
For example, the following file creates `guide.html`, but you open it through `getPageUrl("help")`:

```ts file="../../../../code/entrypoints/page/naming.page.ts" title="src/help.page.ts"
```

When names collide, Addon Bone adds numeric suffixes: `help`, `help1`, `help2`.
One page does not replace another.
Names for API calls and HTML files are assigned separately; check `.adnbn/page.d.ts` for the final name to use in `getPageUrl`.
Set unique `name` and `as` values for stable links.

## Opening a Page

Get the URL through `getPageUrl(name)` from `adnbn` and pass it to `createTab` from `adnbn/browser`, as in the Quick Start.
The function returns a string immediately: `await` is needed to open the tab, not to get the URL.

In the extension's interface, you can use the same URL as a link destination:

```ts file="../../../../code/entrypoints/page/link.page.ts" title="src/navigation.page.ts"
```

The Quick Start's `help.page.ts` must be included in the same build.
Addon Bone maps the name to the actual HTML file, so the calling code does not need to guess the path or account for changes to `as`.

`getPages()` from `adnbn` returns a `Map` of names and relative paths for all included Pages.
Use it to build a menu of extension pages.
For example, if the build includes `help.page.ts` from the Quick Start, `counter.page.ts` from the Vanilla section, and `navigation.page.ts` below, the result looks like this:

```ts file="../../../../code/entrypoints/page/navigation/pages-map.ts" title="getPages()"
```

The key is the page name, and the value is the path to its HTML inside the built extension.
Changing `as` or the output directory changes the path; `getPages()` returns the current value.
The following Page creates a list of links to every page except itself:

```ts file="../../../../code/entrypoints/page/navigation/navigation.page.ts" title="src/navigation.page.ts"
```

`getUrl(path)` from `adnbn/browser` turns the relative path into a full extension URL.
In this example, the list contains links to `counter` and `help`; clicking one opens the selected page in the same tab.
When you add another Page to the build, it appears in the menu automatically.
`getPages()` and `getPageUrl()` work in extension contexts; a link navigation or your browser API call opens the page.

Addon Bone creates `.adnbn/page.d.ts` with the included page names for TypeScript hints and argument checking in `getPageUrl`.

If a name is not found at runtime, the function logs `Cannot find page` and builds a URL from the supplied string; it does not check whether a file exists at that address.

## Page Content

<ViewRendering />

### Vanilla

Pass a DOM element, a non-empty string, or a number directly to `render`, or return one from a function.
For example, the counter creates a button, and Addon Bone places it in a `main` container:

```ts file="../../../../code/entrypoints/page/counter.page.ts" title="src/counter.page.ts"
```

Strings render as text: `"<strong>Hello</strong>"` does not become HTML.
For markup, create DOM elements, use an HTML template, or use React.
An empty string, `null`, `undefined`, and booleans create neither content nor a container.
The number `0` renders.

Vanilla calls `render(options)` when the page loads and uses its synchronous result.
To load data, return an element with initial content and update it from a separate asynchronous function.
Handle errors in that function: Addon Bone does not await its execution.

Changing a variable does not redraw the DOM by itself: the counter's handler updates the button text explicitly.

The component itself must return its result synchronously.

For a reusable function, import `ViewRenderHandler<PageProps>` from `adnbn`; for a React component, use `ViewRenderReactComponent<PageProps>`.
`PageProps` describes the page options the function receives.
Both contracts require a synchronous result.

An explicit annotation is optional: TypeScript also accepts a regular function with an inferred synchronous return type.
In React 19, `React.FC` permits a Promise, so it cannot be passed directly to the strict `render` contract.
Use `ViewRenderReactComponent<PageProps>`, an inferred type, or a synchronous JSX wrapper around an existing synchronous component.
The wrapper does not add support for asynchronous client components.

`container` sets the outer element, and `render` sets what appears inside it.
If you only need a tag, pass a string, such as `container: "main"`.
To set a class or other element properties, pass an object:

    </Tab>
    <Tab label="Container factory">
```ts file="../../../../code/entrypoints/page/container/factory.page.ts" title="src/help.page.ts"
```

The first version creates `main` with the `help-page` class, and `render` returns an `h1` heading inside it.
In the second version, a function creates the same container and adds an `aria-label`, a region name for assistive technologies.
Use a function when you need to call DOM methods or compute container properties from the page options.

In Vanilla, Addon Bone calls the synchronous `render` function, then creates the container, adds it at the start of `body`, and places the returned content inside it.
If you pass a value directly, Addon Bone uses it as-is.

In React, Addon Bone prepares a React element, creates the container, adds it at the start of `body`, and passes the element to React for rendering.
React calls a `render` function supplied as a component when it mounts; React also manages subsequent UI updates.

Do not add the returned elements to `body` yourself.
Both functions receive the page options without `render` and `container`; the examples use `title` for the heading and region name.
The container function can also be asynchronous: Addon Bone awaits its result before mounting.

<DocHeading level={3} id="page-lifecycle" toc={false}>Loading and Closing</DocHeading>

Module code and initial rendering run each time a Page loads.
Multiple open tabs of the same page have separate DOMs and state.
Closing a tab loses its in-memory state; save any data you need in storage.

When rebuilding the interface, Addon Bone first releases the previous result: it unmounts the React root, if one was created, and removes the container.
Release React component subscriptions in the effect's cleanup function.

These settings allow the required capabilities; implement image processing and display in the page's code.
The policy is shared across extension pages: a setting in one Page also applies to the other included pages.
Sandbox has its own separate policy.

Use `CspSource` from `adnbn` for predefined values, and strings for specific addresses:

| Value | What it adds to the policy |
| --- | --- |
| `CspSource.Self` | `'self'`: the extension's own resources |
| `CspSource.None` | `'none'`: blocks resources for the selected directive; use it separately from other sources |
| `CspSource.Data` | `data:`: for example, images from data URLs |
| `CspSource.Blob` | `blob:`: for example, images from Blob URLs |
| `CspSource.UnsafeInline` | `'unsafe-inline'`: for example, inline styles in `sources.style` |

Make the requests in the page's code; `csp` only sets the rules for loading them.

`csp.sources.connect` takes a source, and `hostPermissions` takes a URL pattern with `/*`.

`CspSource.Self` keeps access to the extension's own resources.

Option names differ from the directive names in the generated string:

| Option in `sources` | CSP directive | Use |
| --- | --- | --- |
| `connect` | `connect-src` | `fetch` requests and WebSocket connections |
| `style` | `style-src` | Stylesheets and styles in HTML |
| `font` | `font-src` | Font loading |
| `image` | `img-src` | Images |
| `media` | `media-src` | Audio and video |
| `worker` | `worker-src` | Web Worker |
| `frame` | `frame-src` | Pages inside iframes |
| `child` | `child-src` | Additional rules for nested contexts and workers |

Addon Bone adds `script-src 'self'` and `object-src 'self'` automatically, and also adds `'wasm-unsafe-eval'` when `wasm: true`.
Configure the `csp` object; the framework builds the final manifest string for you.

Choose the settings your interface needs.
If several included pages set `csp`, Addon Bone combines their sources and removes duplicates.
For example, coordinate blocking iframes through `CspSource.None` with the other pages: a source they allow expands the shared policy.

In Chrome Manifest V3, JavaScript code must be packaged with the extension: additional `scripts` do not allow remote code, inline handlers, or `eval`.
`csp` also does not grant browser API permissions or site access.
See [Chrome's CSP rules for extension pages](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy).

## Multi-App Structure

In a project with several apps, put shared pages in `src/shared` and app-specific pages in `src/apps/<app>`.
For a single-app project, use the regular `src` directory; a separate shared layer is not required.

```tree file="../../../../code/entrypoints/page/multi-app.tree"
```

To include both shared help and an app's own dashboard, enable `mergePages`:

```ts file="../../../../code/entrypoints/page/multi-app.config.ts" title="adnbn.config.ts"
```

`mergePages` defaults to `false`:

- With `true`, the build includes pages from the shared layer and the current app together.
- With `false`, if the app has Page files, its entire file set replaces the shared set.
- If the app has no Page files, the shared set is used regardless of `mergePages`.

The app/shared selection happens before build filters are applied.
If an app file is found but then excluded, for example by `includeBrowser`, shared pages are not restored automatically.
Enable `mergePages` to use shared and app-specific pages together.
Options from different files are not merged into one definition.

## Best Practices

- **Open pages through `getPageUrl`.** The name used by the call stays stable when `as` changes if you set a unique `name`.
- **Choose the file extension for the renderer.** `.ts` / `.js` use Vanilla; `.tsx` / `.jsx` use React.
- **Keep required state outside the tab.** Closing or reloading the page recreates its state.
- **Add `matches` only for access from websites.** This option is not needed for navigation inside the extension.
- **Package executable code with the extension.** Connecting a script through HTML does not override the browser's CSP requirements.

## Debugging

1. **HTML is missing from the build.** Check the filename, `pages/` directory, filters, and `mergePages`. Make sure the file is included in the selected page set.
2. **`getPageUrl` reports `Cannot find page`.** Check the name in `.adnbn/page.d.ts` and the current build's filters. After renaming a file, set the previous `name` or update the calls.
3. **The page opens without content.** Check the `render` result and the page's console. Vanilla needs a DOM element, a non-empty string, or a number; React needs a `.tsx` / `.jsx` file and installed dependencies.
4. **Vanilla reports `Vanilla view render must be synchronous`.** Make sure `render` is not declared as `async` and does not return a Promise or an object with a `then` method. Addon Bone does not await this result or create a container. Return the initial content synchronously and load data separately.
5. **HTML tags appear as text.** A string from `render` is displayed literally. Create DOM elements or use JSX or a template for markup.
6. **CSS or an additional script does not load.** Check that the file is in the build and verify its path in `links`, `scripts`, or `tags`. Put ready-to-use resources in `src/public`; check the `template` path relative to the entrypoint.
7. **A link from a website is blocked.** Check `matches` and `web_accessible_resources` in the final manifest. For Manifest V3, specify the site's origin with the path `/*`.
8. **Page name hints are missing.** Check that `.adnbn/page.d.ts` exists and that the generated declarations are included in the project's TypeScript configuration.
9. **A browser API is unavailable or returns incomplete data.** Check the permission in the final manifest's `permissions` and the conditions for including the Page. Reload the built extension after changing permissions.
10. **A server request is blocked.** Check the address in `host_permissions` for Manifest V3 or `permissions` for Manifest V2, and the source in CSP `connect-src`. If site access is optional, get the user's approval first; a pattern in the manifest does not mean access has been granted.
11. **A permission remains after excluding a Page.** Check other included entrypoints and the extension configuration: Addon Bone combines their requirements.
