# Command

Command lets you run extension actions with a keyboard shortcut: for example, open a page, toggle a setting, or perform an operation on the current tab.
For the extension's toolbar button, use `defineExecuteActionCommand`.

Create a command file, choose a shortcut, and describe the action in `execute`.
Addon Bone adds the command to the manifest and connects the handler to the background context.
You do not need to create a separate `background.ts` or register a command event listener.

## Quick Start

Let's create a command that logs a message and the current tab to the background console when you press a shortcut.

```ts title="src/command.ts"
import {defineCommand} from "adnbn";

export default defineCommand({
    defaultKey: "Ctrl+Shift+Y",
    execute(tab) {
        console.log("Command executed", tab);
    },
});
```

Add the file to your Addon Bone project, build the extension, and load it in the browser.
In Chrome, open `chrome://extensions`, enable Developer mode, and click the service worker link on the extension's card.
Return to a regular tab and press `Ctrl+Shift+Y`, or `Command+Shift+Y` on macOS.
The background console will show `Command executed` and the tab, if the browser provided one.

Addon Bone takes the name `command` from the filename and registers the shortcut.
This example needs no additional permissions.
If the shortcut does not work, check its assignment in `chrome://extensions/shortcuts`: the browser, operating system, or another extension may already use it.

## File Structure

Addon Bone discovers commands by their filenames and directories.
Place them in `src`, or group them in `commands/` if that makes your project easier to organize.

package.json

For TypeScript files, the following paths are supported:

- `command.ts` and `*.command.ts`;
- `command/index.ts` and `*.command/index.ts`;
- `commands/command.ts` and `commands/*.command.ts`;
- `commands/command/index.ts` and `commands/*.command/index.ts`.

:::warning Discovery scope
If `commands/` contains command files, Addon Bone uses only those files for that source scope.
It does not include command files at the top level of the same scope.
This rule applies separately to app sources and the shared layer, before filtering by browser, app, or manifest version.
:::

<DocHeading level={3} id="command-names" toc={false}>Command Names</DocHeading>

The command name becomes a key in `manifest.commands` and connects the shortcut to its handler.
If you omit `name`, Addon Bone takes the name from the file or directory:

| File | Default name |
| --- | --- |
| `command.ts` or `command/index.ts` | `command` |
| `open.command.ts` or `open.command/index.ts` | `open` |
| `commands/open.command.ts` | `open` |

Set `name` explicitly if it should stay the same after you rename the file.
This also helps preserve the user's shortcut assignment.

:::warning Duplicate names
Included commands must have unique names.
If names match, Addon Bone stops the build and identifies both files; it does not add numeric suffixes.
This also applies to commands from the shared layer and plugins.
:::

<DocHeading level={2} id="definition">Defining a Command</DocHeading>

Use `defineCommand` to get option suggestions and type checking.
Alternatively, use named exports for the options and `export default` for the handler.

<Tabs>
    <Tab label="Using defineCommand">
```ts title="src/show-tab.command.ts"
import {defineCommand} from "adnbn";

export default defineCommand({
    name: "show-tab",
    description: "Show current tab",
    defaultKey: "Ctrl+Shift+Y",
    execute(tab) {
        console.log("Current tab", tab?.id);
    },
});
```
    </Tab>
    <Tab label="Named exports">
```ts title="src/show-tab.command.ts"
export const name = "show-tab";
export const description = "Show current tab";
export const defaultKey = "Ctrl+Shift+Y";

export default (tab?: chrome.tabs.Tab) => {
    console.log("Current tab", tab?.id);
};
```
    </Tab>
</Tabs>

Both formats support the same options, permissions, and build filters.
In the named-export format, declare options with `export const`; a bare `export default` corresponds to `execute`.
The `primary` badge beside the option marks this mapping.

<DocHeading level={2} id="execute-function">The execute Handler</DocHeading>

In `execute`, implement the action to perform when the command is called.
The handler runs in the background and can call browser APIs.
It runs when the shortcut is pressed, rather than each time the background context starts.

```ts title="src/command.ts"
import {defineCommand} from "adnbn";

export default defineCommand({
    defaultKey: "Ctrl+Shift+Y",
    execute(tab, options) {
        console.log("Command", options.name);
        console.log("Current tab", tab?.id);
    },
});
```

The first argument is the active tab, if the browser provided one.
It can be `undefined`; check the tab and its `id` if your action depends on them.
The tab object does not guarantee access to its URL or title: reading these fields requires the appropriate permissions.

The second argument contains the current command's options, including the name determined during the build.
Options from other files are not merged into this object.

For asynchronous work, declare `async execute` and use `await` inside it.
Pressing the shortcut again can start another call before the previous one finishes: Addon Bone does not queue calls.
If the action must not run concurrently, handle this in your code.

If `execute` throws or returns a rejected promise, Addon Bone logs the error to the background console.
The framework does not retry the action automatically.
Handle errors inside `execute` when you need to try another approach or tell the user what happened.

Commands follow the background lifecycle.
In Chrome Manifest V3, the browser can stop an inactive service worker, so in-memory state does not persist between starts.
Keep long-lived data in extension storage; see the [Background lifecycle](./background#lifecycle) for details.

## Keyboard Shortcuts

`defaultKey` sets the shortcut for platforms without a separate value.
To choose a different shortcut for a particular system, use `windowsKey`, `macKey`, `chromeosKey`, or `linuxKey`.
If you set only platform-specific values, the command will have no initial shortcut on other systems.

Addon Bone requires at least one of these options for every command, including the extension button command.
Browsers allow commands without an initial shortcut, but the current Addon Bone validation does not accept these definitions.

<DocHeading level={3} id="shortcut-format" toc={false}>Shortcut Format</DocHeading>

Write the shortcut without spaces, separating keys with `+`: for example, `Ctrl+Shift+Y` or `Alt+U`.
Put modifiers first and the key last.
Do not repeat the same modifier.
For Chrome and Firefox, use no more than two modifiers and one key.

Chrome and Firefox support letters `A`–`Z`, digits `0`–`9`, and `Comma`, `Period`, `Home`, `End`, `PageUp`, `PageDown`, `Space`, `Insert`, `Delete`, `Up`, `Down`, `Left`, and `Right`.
Key names are case-sensitive.
Specify media keys `MediaNextTrack`, `MediaPlayPause`, `MediaPrevTrack`, and `MediaStop` on their own, without modifiers.

<DocHeading level={4} id="chromium-shortcuts" toc={false}>Chrome, Chromium, Edge, and Opera</DocHeading>

When building for Chrome, Chromium, Edge, or Opera, use `Ctrl` or `Alt` and optionally `Shift`.
In `macKey`, you can also use `Command`, `MacCtrl`, and `Option`; in `chromeosKey`, you can use `Search`, for example `Search+Y` or `Search+Shift+Y`.
On macOS, the browser treats `Ctrl` as `Command`; for the Control key, use `MacCtrl` in `macKey`.

These browsers also accept `Tab`, but do not accept `F1`–`F12`.

In Chromium, you cannot combine `Alt` or `Option` with `Ctrl`, `Command`, `MacCtrl`, or `Search`.
Addon Bone also checks equivalent macOS modifiers: for example, `Command+Option+Y` stops the build, as does `Ctrl+Alt+Y`.
This restriction avoids conflicts with `AltGr`; see the [Chrome rules](https://developer.chrome.com/docs/extensions/reference/api/commands#key-combination-requirements) and [Chromium shortcut validation](https://github.com/chromium/chromium/blob/main/ui/base/accelerators/command.cc).

Use no more than two modifiers in `chromeosKey` as well: desktop Chromium versions validate shortcuts for all platforms.
`Search+Shift+Y` therefore passes validation, while `Search+Ctrl+Shift+Y` does not.

<DocHeading level={4} id="firefox-shortcuts" toc={false}>Firefox</DocHeading>

In Firefox, you can use `Ctrl`, `Alt`, `Command`, or `MacCtrl`, then add `Shift` or another modifier from this list as the second modifier.
For example, `Ctrl+Alt+Y` works in a Firefox build.
Firefox treats `Ctrl` and `Command` as the same modifier, so you cannot combine them.

Firefox also accepts `F1`–`F12`, including shortcuts without a modifier: `F12` or `Shift+F12`.
`Option` and `Tab` are not supported in Firefox; see the [Firefox shortcut format](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/commands#shortcut_values).

In Firefox builds, `chromeosKey` is not checked for Firefox compatibility: the browser does not use it on its platforms.

<DocHeading level={3} id="shortcut-validation" toc={false}>Build Validation</DocHeading>

If a shortcut is invalid, the build stops and identifies the file and option.
Fix spaces, unknown key names, and incorrect key order even in files excluded by filters: Addon Bone checks the common format before filtering.

Browser compatibility is checked only for commands included in the build.
For shortcuts available in just one browser, set `includeBrowser`, for example `includeBrowser: ["firefox"]` for a command with `Ctrl+Alt+Y`.

<DocHeading level={3} id="global-shortcuts" toc={false}>Global Shortcuts</DocHeading>

By default, a shortcut works when the browser has focus.
In Chrome, Chromium, Edge, and Opera, `global: true` lets you run the command from another application as well.

For regular global shortcuts, use `Ctrl+Shift+0`–`Ctrl+Shift+9`; `macKey` also accepts `Command+Shift+0`–`Command+Shift+9`.
Addon Bone checks the shortcut used on each desktop platform: the platform-specific value, or `defaultKey` if none is set.
Media keys do not require this numeric format.

Chrome on ChromeOS does not support [global commands](https://developer.chrome.com/docs/extensions/reference/api/commands#scope).
Do not set `chromeosKey` together with `global: true`: Addon Bone stops such a build for Chromium.
For a regular command on ChromeOS, use `chromeosKey` without `global: true`.

Firefox and Safari do not support global commands.
If you set `global: true`, Addon Bone warns and continues the build, but the shortcut works only in the browser.

<DocHeading level={3} id="shortcut-assignment" toc={false}>Changing Shortcuts in the Browser</DocHeading>

The shortcut in your source code sets an initial value that the user can change in the browser settings.
If the browser or another extension already uses it, the command may be left without a shortcut.
In Chrome, use `chrome://extensions/shortcuts`; in Firefox, manage extension shortcuts in `about:addons`.

Chrome allows no more than four suggested shortcuts for one extension.
Count all included commands, including those from the shared layer and plugins.
Browser rules are described in the [Chrome Commands API](https://developer.chrome.com/docs/extensions/reference/api/commands) and [MDN documentation](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/commands).

<DocHeading level={2} id="execute-action-command">Extension Button</DocHeading>

Use `defineExecuteActionCommand` when the browser toolbar button should perform an action.
The user can trigger it by clicking the button or pressing its assigned shortcut.

<Tabs>
    <Tab label="Using defineExecuteActionCommand">
```ts title="src/action.command.ts"
import {defineExecuteActionCommand} from "adnbn";

export default defineExecuteActionCommand({
    defaultKey: "Ctrl+Shift+U",
    execute(tab) {
        console.log("Action command executed", tab);
    },
});
```
    </Tab>
    <Tab label="Named exports">
```ts title="src/action.command.ts"
export const name = "_execute_action";
export const defaultKey = "Ctrl+Shift+U";

export default (tab?: chrome.tabs.Tab) => {
    console.log("Action command executed", tab);
};
```
    </Tab>
</Tabs>

In source code and the handler's `options.name`, the button command is named `_execute_action`.
Addon Bone connects `execute` to the button click event and chooses the manifest fields for the manifest version:

| Manifest version | Name in `commands` | Button field |
| --- | --- | --- |
| Manifest V3 | `_execute_action` | `action` |
| Manifest V2 | `_execute_browser_action` | `browser_action` |

Use the same `defineExecuteActionCommand`, or named exports with `name = "_execute_action"`, for both versions.
If the button has not been declared yet, it will appear in the generated manifest.
A build can contain only one such command; a second file with this name stops the build.

If the button has a popup, the browser opens it and does not call this `execute`.
If you need both a popup and a shortcut for an action, declare a separate regular command with `defineCommand`.
This behavior is described in the [Action API documentation](https://developer.chrome.com/docs/extensions/reference/api/action#popup).

Configure the button's icon and tooltip through [`action` in `adnbn.config.ts`](../configuration/config.mdx#toolbar-action).
These settings control its appearance; the command defines the action to perform.

## Multi-App Structure

In a project with multiple apps, place shared commands in `src/shared` and app-specific commands in `src/apps/<app>`.
In a single-app project, use the regular `src`; no separate shared layer is needed.

```tree
src
├── shared/
│   └── open.command.ts
└── apps/
    ├── app-a/
    │   └── toggle.command.ts
    └── app-b/
        └── search.command.ts
adnbn.config.ts
package.json
```

<span id="multi-app-configuration" />

To include both shared commands and the current app's commands, enable `mergeCommands`:

```ts title="adnbn.config.ts"
import {defineConfig, Workspace} from "adnbn";

export default defineConfig({
    workspace: Workspace.Multi,
    mergeCommands: true,
});
```

<span id="multi-app-merge" />

`mergeCommands` defaults to `false`:

- With `true`, the build includes commands from the shared layer and the current app.
- With `false`, if the app has its own command files, its entire command set replaces the shared set.
- If the app has no command files, the shared set is used.

The app/shared selection happens before entrypoint filters are applied.
If an app command is found but then excluded, for example by `manifestVersion`, shared commands are not brought back automatically.

When files are combined, each command keeps its own options and `execute`.
Matching names do not replace a shared command with a local one: they stop the build.
For different implementations of one command, set filters so the build includes only one file with that name.

## Best Practices

<span id="best-practices-critical" />
<span id="best-practices-recommended" />

- **Choose unique names.** An explicit `name` helps preserve the command and user assignments when you rename a file.
- **Check the shortcut assignment in the browser.** The value in your source code does not guarantee that the shortcut is available or that the user has kept it unchanged.
- **Handle a missing tab.** Check `tab` and the fields you need before performing the action.
- **Declare permissions alongside the command.** Filters can exclude another file whose permissions you rely on.
- **Account for repeated calls.** Asynchronous handlers can run concurrently; keep long-lived state outside background memory.

## Debugging

1. **The command is missing.** Check the filename, location, build filters, and `mergeCommands`. Make sure `commands/` has not changed the discovery scope, and look for the command in `manifest.commands`.
2. **The build reports duplicate names.** Check both identified files, including the shared layer and plugins. Choose different names or exclude one implementation with filters.
3. **The shortcut does not work.** Check its assignment in `chrome://extensions/shortcuts` or Firefox's extension settings. Try another available shortcut, and make sure the browser has focus if the command is not global.
4. **There is no output from execute.** Open the background DevTools and check messages and errors there. The web page console does not show the command handler's output.
5. **The button opens a popup instead of running the action.** If a popup is set for the current tab, the button command's `execute` is not called. Run the action from the popup or through a separate regular command.
6. **The tab or its fields are missing.** Check `tab`, `tab.id`, and the permissions needed to read the URL or title. Do not assume these fields are available on every call.
