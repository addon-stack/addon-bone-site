Popup создаёт небольшое окно, которое пользователь открывает нажатием на кнопку расширения в браузере.
Используйте его для быстрых действий с текущей вкладкой, просмотра состояния расширения и управления его функциями.

Разместите код в `popup.ts` или `popup.tsx`.
Вы можете работать с DOM напрямую или использовать React; Addon Bone создаст HTML, подключит код страницы и назначит Popup кнопке расширения.

Сигнатуры функций, типы и собственные опции собраны в [API всплывающего окна](/api/adnbn/popup).

## Быстрый старт

Создадим Popup с простым текстом, доступным по нажатию кнопки расширения:

```ts file="../../../../code/entrypoints/popup/popup.ts" title="src/popup.ts"
```

Добавьте файл в проект Addon Bone, соберите расширение и загрузите его в браузер.
Нажмите на значок расширения в панели инструментов или в меню расширений; при необходимости закрепите его на панели.
В открывшемся окне появится текст `Your extension is ready.`, а подсказкой кнопки будет `Open quick actions`.
`title` задаёт заголовок HTML-документа; `tooltip` — текст подсказки при наведении на кнопку расширения.

Addon Bone создаст `popup.html` и запишет его путь в `action.default_popup` для Manifest V3 или `browser_action.default_popup` для Manifest V2.
Строку из `render` фреймворк отобразит как текст, создав контейнер автоматически.
Для примера не нужны дополнительные файлы, React или разрешения.

## Открытие и закрытие

Браузер загружает Popup при открытии и уничтожает его документ после закрытия.
Переменные, DOM и состояние React создаются заново при следующем открытии.
Сохраняйте нужные данные в хранилище расширения; длительную работу передавайте в [Background](./background.mdx) или [Service](./service.mdx).

Нажатие за пределами Popup закрывает окно.
В Chrome удержать его открытым после потери фокуса нельзя; для продолжительной работы с интерфейсом используйте отдельную [страницу расширения](./page.mdx) или [Sidebar](./sidebar.mdx).
Подробнее — [жизненный цикл Popup в Chrome](https://developer.chrome.com/docs/extensions/develop/ui/add-popup).

Когда кнопке назначен Popup, событие `action.onClicked` не вызывается.
Разместите действия, связанные с интерфейсом, в его обработчиках, а начальную загрузку данных — в коде страницы или эффектах React.
Правило относится и к `browserAction.onClicked` в Manifest V2.
Смотрите [поведение кнопки расширения](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/user_interface/Toolbar_button#specifying_the_browser_action).

Размер окна зависит от содержимого и ограничений браузера.
В Chrome Popup автоматически подстраивается в пределах от 25 × 25 до 800 × 600 пикселей.
Задавайте ширину, отступы и перенос длинных строк через стили; отдельной опции размера у `definePopup` нет.
Пример показан в [разделе стилей](#стили-и-модули), а ограничения Chrome — в [описании Popup для Action API](https://developer.chrome.com/docs/extensions/reference/api/action#popup).

## Структура файлов

Addon Bone находит Popup по имени файла или каталога.
Можно хранить файлы непосредственно в `src` или группировать их в `popups/`:

<Tabs>
    <Tab label="Обычная структура">
```tree file="../../../../code/entrypoints/popup/default.tree"
```
    </Tab>
    <Tab label="Группировка файлов">
```tree file="../../../../code/entrypoints/popup/grouped.tree"
```
    </Tab>
</Tabs>

Каталог `account.popup/` с файлом `index.tsx` объявляет Popup с алиасом `account`.
Вместо каталога можно использовать одиночный файл `account.popup.tsx`.
Выбирайте каталог, когда хотите хранить рядом компоненты, стили и ресурсы этого Popup.

Для TypeScript поддерживаются следующие пути; `{ts,tsx}` обозначает два возможных расширения:

- `popup.{ts,tsx}` и `*.popup.{ts,tsx}`;
- `popup/index.{ts,tsx}` и `*.popup/index.{ts,tsx}`;
- `popups/popup.{ts,tsx}` и `popups/*.popup.{ts,tsx}`;
- `popups/popup/index.{ts,tsx}` и `popups/*.popup/index.{ts,tsx}`.

Используйте `.ts` для Vanilla и `.tsx` для React.
Для JavaScript используйте те же пути с `.js` или `.jsx`: `.js` выбирает Vanilla, а `.jsx` — React.
Поиск также распознаёт `.vue` и `.svelte`, но встроенных View-адаптеров для этих форматов сейчас нет; для готовых примеров используйте Vanilla или React.

:::warning Область поиска
Если Addon Bone найдёт точки входа в `popups/`, он использует эту папку вместо Popup-файлов на верхнем уровне той же области исходников.
Например, при наличии `popups/account.popup/index.tsx` файл `popup.ts` рядом с папкой не участвует в сборке.
Правило действует отдельно для shared-слоя и приложения, до фильтров: исключение найденного файла фильтром не возобновляет поиск на верхнем уровне.
:::

<DocHeading level={3} id="popup-selection" toc={false}>Выбор реализации</DocHeading>

При `multiplePopup: false`, значении по умолчанию, в сборку входит один Popup.
После применения фильтров Addon Bone выбирает последний файл по приоритету: файлы приложения имеют преимущество перед shared-слоем и плагинами, а среди локальных файлов одного уровня выбирается последний по порядку путей.
Остальные кандидаты не создают HTML, не входят в `getPopups()` и не добавляют разрешения или CSP.

Для одной реализации оставляйте один подходящий файл или разделяйте варианты фильтрами, например `includeBrowser` и `includeApp`.
Для переключения между несколькими собранными интерфейсами используйте [несколько Popup](#несколько-popup).

## Объявление Popup

Используйте [`definePopup`](/api/adnbn/popup#definepopup), чтобы получить подсказки опций и проверку типов.
Вместо него можно объявить опции именованными экспортами, а содержимое или функцию отображения — через `export default`.

В этом примере React-компонент показывает заголовок текущей вкладки по нажатию кнопки в Popup.
Разрешение `activeTab` даёт временный доступ к заголовку после нажатия пользователем кнопки расширения; постоянный доступ ко всем вкладкам для примера не нужен.
`getActiveTab` из `adnbn/browser` находит активную вкладку текущего окна.
Для этого примера нужен React 19 или новее, а также `react-dom`, `@types/react` и `@types/react-dom`; команды установки приведены в [разделе React](#react).
Выберите один из двух форматов `popup.tsx` и сохраните рядом файл `CurrentTab.tsx`:

<Tabs>
    <Tab label="Через definePopup">
```tsx file="../../../../code/entrypoints/popup/current-tab/popup.tsx" title="src/popup.tsx"
```
    </Tab>
    <Tab label="Именованные экспорты">
```tsx file="../../../../code/entrypoints/popup/current-tab/popup.named-exports.tsx" title="src/popup.tsx"
```
    </Tab>
    <Tab label="Данные вкладки">
```tsx file="../../../../code/entrypoints/popup/current-tab/CurrentTab.tsx" title="src/CurrentTab.tsx"
```
    </Tab>
</Tabs>

Этот вариант заменяет `popup.ts` из быстрого старта.
Соберите расширение, загрузите его заново, откройте обычную веб-страницу и нажмите кнопку расширения.
Нажмите **Read current tab** в Popup: во время запроса кнопка покажет `Loading…` и будет недоступна, затем под ней появится заголовок вкладки или сообщение об ошибке.
После повторного открытия Popup нажмите кнопку снова: результат хранится только в состоянии компонента.

[`useActionState`](https://react.dev/reference/react/useActionState) хранит результат операции в `message` и возвращает `isPending`, пока запрос выполняется.
Обработчик возвращает заголовок при успехе или сообщение при ошибке.
Через `action={load}` React запускает обработчик при отправке формы и отслеживает его выполнение; отдельный вызов `startTransition` не нужен.

`activeTab` не даёт постоянного доступа ко всем сайтам и не снимает ограничения служебных страниц браузера.
При переходе на другой сайт временный доступ отзывается; новое нажатие кнопки расширения предоставляет его снова.
Подробнее — [возможности и условия `activeTab`](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab).

Оба формата поддерживают одни и те же опции и фильтры сборки.
В формате с именованными экспортами задавайте опции через `export const`; обычный `export default` соответствует `render`.
Готовый React-компонент экспортируйте напрямую, как `export default CurrentTab` в примере.
В описании опций это соответствие обозначено бейджем **primary**.

Для постоянного текста передайте строку напрямую, как в [быстром старте](#быстрый-старт).
Функция нужна, когда содержимое создаётся или вычисляется при загрузке страницы.
`render` необязателен: если вся разметка находится в HTML-шаблоне, достаточно задать `template` и остальные опции страницы.

## Содержимое страницы

<ViewRendering />

### Vanilla

Передайте в `render` DOM-элемент, непустую строку или число напрямую либо верните их из функции.
Этот счётчик создаёт кнопку; Addon Bone помещает её в контейнер `main`:

```ts file="../../../../code/entrypoints/popup/counter.popup.ts" title="src/popup.ts"
```

При нажатии обработчик увеличивает значение и обновляет текст кнопки.
Изменение переменной само по себе не перерисовывает DOM.
После закрытия окна значение сбросится: этот пример хранит счётчик только в памяти Popup.

Строка отображается как текст: `"<strong>Hello</strong>"` не превращается в HTML.
Для разметки создавайте DOM-элементы, используйте HTML-шаблон или React.
Пустая строка, `null`, `undefined` и логические значения не создают содержимое или контейнер; число `0` отображается.

Vanilla вызывает `render(options)` при загрузке страницы и использует его синхронный результат.
Для загрузки данных верните элемент с начальным содержимым, затем обновите его из отдельной асинхронной функции.
Обрабатывайте ошибки в этой функции: Addon Bone не ожидает её выполнения.

### React

Установите `react` и `react-dom`, если их ещё нет в проекте.
Для TypeScript также нужны `@types/react` и `@types/react-dom`.
Выполните команды в каталоге проекта; для JavaScript достаточно первой строки:

<PackageManagerTabs command={reactInstallCommands} />

Сохраните точку входа как `popup.tsx`: расширение файла выберет React.
Для JavaScript с JSX используйте `popup.jsx`.
В этом примере компонент счётчика объявлен в файле точки входа и передан в `render`:

```tsx file="../../../../code/entrypoints/popup/counter.popup.tsx" title="src/popup.tsx"
```

Передайте готовый компонент напрямую через `render: Counter`.
Эта реализация `popup.tsx` заменяет предыдущий Popup из примеров.

Нажатие кнопки обновит состояние через `useState`, и React отобразит новое значение.
Addon Bone создаёт контейнер и React root; вручную вызывать `createRoot` не нужно.
Функция `render` в React выполняется как компонент и может использовать hooks.
Сохраните импорт `React` из примера: текущее преобразование JSX использует его при выполнении.
Загружайте данные через эффекты или выбранную библиотеку загрузки данных: сначала покажите начальное содержимое, затем обновите состояние.
Сам компонент возвращает результат синхронно.

<DocHeading level={3} id="popup-render-types" toc={false}>Типы `render` и `props`</DocHeading>

Для переиспользуемой функции используйте [`ViewRenderHandler<PopupProps>`](/api/adnbn/view#viewrenderhandler), а для React-компонента — [`ViewRenderReactComponent<PopupProps>`](/api/adnbn/view#viewrenderreactcomponent).
[`PopupProps`](/api/adnbn/popup#popupprops) описывает опции текущего Popup, включая заголовок документа `title` и подсказку кнопки `tooltip`.
В текущем фреймворке этот тип не экспортируется из `adnbn` напрямую. В примерах ниже локальный алиас выводится из параметра [`definePopup`](/api/adnbn/popup#definepopup) с исключением `render` и `container`.
Оба контракта требуют синхронного результата:

<FrameworkTabs>
    <Tab label="Vanilla">
```ts file="../../../../code/entrypoints/popup/typed.popup.ts" title="src/popup.ts"
```
    </Tab>
    <Tab label="React">
```tsx file="../../../../code/entrypoints/popup/typed.popup.tsx" title="src/popup.tsx"
```
    </Tab>
</FrameworkTabs>

Явная аннотация необязательна: можно передать обычную функцию с выведенным синхронным типом результата.
Тип `React.FC` в React 19 допускает Promise, поэтому для строгого контракта `render` используйте `ViewRenderReactComponent<PopupProps>` или выведенный синхронный тип.

<DocHeading level={3} id="container-examples" toc={false}>Контейнер для содержимого</DocHeading>

`container` задаёт внешний элемент, а `render` — его содержимое.
Для выбора тега достаточно строки, например `container: "main"`.
Для свойств элемента передайте объект; для вызова DOM-методов или вычисления свойств по опциям страницы — функцию:

<Tabs>
    <Tab label="Свойства контейнера">
```ts file="../../../../code/entrypoints/popup/container/options.popup.ts" title="src/popup.ts"
```
    </Tab>
    <Tab label="Создание контейнера">
```ts file="../../../../code/entrypoints/popup/container/factory.popup.ts" title="src/popup.ts"
```
    </Tab>
</Tabs>

Оба варианта создают `main` с классом `popup-content`; функция дополнительно задаёт `aria-label` для вспомогательных технологий.
`render` создаёт заголовок `h1` внутри контейнера.
Обе функции получают опции текущего файла без `render` и `container`.

В Vanilla Addon Bone получает результат `render`, создаёт контейнер, добавляет его в начало `body` и помещает внутрь содержимое.
В React фреймворк сначала подготавливает React-элемент, затем создаёт и добавляет контейнер, после чего передаёт элемент React для отображения.
React вызывает компонент при монтировании и управляет дальнейшими обновлениями интерфейса.

Не добавляйте возвращаемые элементы в `body` самостоятельно.
Функция контейнера может быть асинхронной: Addon Bone дождётся её результата перед монтированием.

Для React используйте `index.tsx`.
Это необязательная организация файлов: одиночный `popup.ts` также поддерживается.

## Несколько Popup

Включите `multiplePopup: true` в `adnbn.config.ts`, если расширению нужны несколько интерфейсов кнопки.
Addon Bone создаст HTML для каждого подходящего файла, но в манифесте кнопке назначит только один Popup.
Это настройка сборки; она не открывает несколько окон одновременно.

В этом примере пользователь выбирает интерфейс кнопки на странице [Options](./options.mdx).
Два Popup выводят разный текст, чтобы результат переключения был сразу виден.
Форма в Options получает доступные варианты через [`getPopups()`](/api/adnbn/popup#getpopups) и назначает выбранный Popup через [`changePopup`](/api/adnbn/popup#changepopup).
Подписями кнопок служат алиасы собранных Popup:


```ts file="../../../../code/entrypoints/popup/variants/popup.ts" title="src/popup.ts"
```
    </Tab>
    <Tab label="Второй Popup">
```ts file="../../../../code/entrypoints/popup/variants/second.popup.ts" title="src/second.popup.ts"
```

```tsx file="../../../../code/entrypoints/popup/variants/options.tsx" title="src/options.tsx"
```
    </Tab>

Добавьте `multiplePopup` в существующую конфигурацию, сохранив остальные настройки.
Этот сценарий заменяет предыдущие Popup-файлы.
Для формы в Options нужен React 19 или новее; команды установки приведены в [разделе React](#react).
Дополнительные разрешения и файлы для примера не нужны.
Если страница Options уже есть, перенесите в неё форму выбора вместо создания второй страницы.

Соберите расширение, загрузите его заново и откройте его настройки.
Нажмите **second**, дождитесь сообщения `Popup selected.` и нажмите кнопку расширения: появится текст `This is the second popup.`.
Нажмите **popup** и снова откройте Popup: теперь появится `This is the first popup.`.
`getPopups().keys()` возвращает алиасы собранных Popup: в этом примере `popup` и `second`.
Каждая кнопка передаёт свой алиас в обработчик, который вызывает `changePopup`; при добавлении нового Popup список обновится после сборки.

[`useActionState`](https://react.dev/reference/react/useActionState) хранит сообщение об успехе или ошибке и возвращает `isPending`, пока переключение выполняется.
В этот момент кнопки недоступны, а форма показывает `Applying…`.
Через `formAction={() => apply(alias)}` React запускает обработчик в контексте Action и отслеживает выполнение операции; отдельный вызов `startTransition` не нужен.

Для восстановления выбора после перезапуска браузера сохраните алиас в хранилище и применяйте его из [Background](./background.mdx) при запуске.
Для переходов между экранами уже открытого Popup меняйте состояние React или используйте маршрутизацию внутри его страницы.

<DocHeading level={3} id="popup-apply" toc={true}>Начальный Popup</DocHeading>

При `multiplePopup: true` начальным становится первый собранный Popup с `apply: true` или без этой опции.
Порядок начинается с файлов плагинов, затем shared-слоя и приложения; локальные файлы одного уровня идут по порядку путей.
Для явного выбора задайте `apply: false` остальным вариантам, как в примере.
При `multiplePopup: false` сначала выбирается единственный файл по [правилам приоритета](#popup-selection), затем проверяется его `apply`.

`apply: false` не исключает файл из сборки: его HTML и алиас остаются доступны, а разрешения и CSP учитываются.
Если ни один собранный Popup не применяется, Addon Bone не задаёт `default_popup`.
Сам по себе такой набор также не добавляет поле `action` / `browser_action`; оно может появиться из конфигурации `action` или команды `_execute_action`.
Если хотите назначать Popup только из кода, объявите `action: {}` в конфигурации проекта и оставьте `apply: false` у всех вариантов.

<DocHeading level={3} id="popup-runtime" toc={true}>Переключение во время работы</DocHeading>

[`getPopups()`](/api/adnbn/popup#getpopups) из `adnbn` возвращает [`PopupMap`](/api/adnbn/popup#popupmap) — `Map<PopupAlias, PopupMapEntry>` с алиасами собранных Popup и данными для переключения.
Типы `PopupMap`, [`PopupAlias`](/api/adnbn/popup#popupalias) и [`PopupMapEntry`](/api/adnbn/popup#popupmapentry) также доступны из `adnbn`.
У `PopupMapEntry` три необязательных поля:

- `path?: string` — путь к HTML внутри расширения;
- `tooltip?: string` — исходный текст подсказки или ключ локализации, например `@popup.account`;
- `icon?: string` — имя группы иконок.

Заголовок документа `title` в этот список не входит: он остаётся опцией страницы и доступен в [`PopupProps`](/api/adnbn/popup#popupprops).
`getPopups()` не переводит `tooltip`; если меню нужны подписи вариантов, задавайте их отдельно от подсказки кнопки.
Алиасы зависят от имени файла или `as`; таблица приведена в [результате сборки](#результат-сборки).
В `.adnbn/popup.d.ts` Addon Bone дополняет [`PopupAliasRegistry`](/api/adnbn/popup#popupaliasregistry) именами вариантов для подсказок TypeScript.

[`changePopup(alias, tab?)`](/api/adnbn/popup#changepopup) возвращает `Promise<void>`.
Вызывайте его из background или страницы расширения.
Без второго аргумента он меняет Popup для кнопки в целом; передайте ID вкладки или объект вкладки, чтобы задать переопределение для неё.
Переопределение вкладки имеет преимущество перед общим значением и сбрасывается при её закрытии.
Подробнее — [настройки action для отдельной вкладки](https://developer.chrome.com/docs/extensions/reference/api/action#per-tab_state).

Вызов меняет то, что откроется при следующем нажатии кнопки; уже открытый документ он не заменяет и новое окно не открывает.
Если у выбранного Popup есть `tooltip` или `icon`, `changePopup` также меняет соответствующие свойства кнопки.
Отсутствующее поле оставляет текущее значение кнопки без изменений; значения из конфигурации автоматически не восстанавливаются.
Заголовок HTML-документа берётся из `title` выбранного Popup при его загрузке.

Обрабатывайте ошибку вызова: алиас может отсутствовать в текущей сборке или браузер может отклонить изменение.
Путь Popup, подсказка и иконка меняются последовательно.
Если изменение подсказки или иконки завершится ошибкой, уже выполненные изменения сохранятся.

Для программного открытия уже назначенного Popup используйте `openActionPopup()` из `adnbn/browser`.
Эта функция возвращает `Promise<void>`; при необходимости принимает ID окна.
Поддержка зависит от браузера и версии: в Chrome Manifest V3 метод доступен обычным расширениям с Chrome 127; в версиях 118–126 — только установленным политикой.
Проверяйте совместимость целевого браузера и обрабатывайте отказ открытия.
Смотрите [контракт `action.openPopup()` в Chrome](https://developer.chrome.com/docs/extensions/reference/api/action#method-openPopup) и [совместимость браузеров](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/action/openPopup#browser_compatibility).

Пустое значение не гарантирует скрытую подсказку: браузер определяет её отображение и может показать название расширения.
Подробнее — [поведение пустого значения в браузере](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/action/setTitle).

## Опции

Опции [`PopupDefinition`](/api/adnbn/popup#popupdefinition) относятся к конкретному Popup: задают его содержимое, настройки HTML, начальное назначение кнопке и условия включения в сборку. Собственные поля кнопки объединяет [`PopupConfig`](/api/adnbn/popup#popupconfig).
`multiplePopup` и `mergePopup` задаются в конфигурации проекта, а не внутри `definePopup`.

## Multi-App Structure

В проекте с несколькими приложениями поместите общий Popup в `src/shared`, а реализацию конкретного приложения — в `src/apps/<app>`:

```tree file="../../../../code/entrypoints/popup/multi-app.tree"
```

Включите multi-app режим в конфигурации проекта:

```ts file="../../../../code/entrypoints/newtab/multi-app.config.ts" title="adnbn.config.ts"
```

При `mergePopup: false`, значении по умолчанию, файлы приложения заменяют shared-набор.
Если у приложения своих Popup-файлов нет, Addon Bone использует shared-набор.
При `mergePopup: true` он собирает кандидатов из обоих слоёв.
Опции разных файлов не сливаются в одно определение.

`mergePopup` управляет составом кандидатов, а `multiplePopup` — числом создаваемых страниц.
При `multiplePopup: false` после объединения и фильтров всё равно выбирается один Popup; реализация приложения имеет преимущество перед shared-слоем.
При `multiplePopup: true` подходящие файлы становятся отдельными страницами; начальную выбирайте через `apply`.
Для shared- и app-вариантов, которые должны одновременно войти в сборку, используйте разные имена или `as`.
В single-app проекте используйте обычный `src`; отдельный shared-слой не требуется.

Выбор набора приложения или shared-слоя происходит до фильтров.
При выключенном слиянии найденный, но затем исключённый файл приложения не возвращает общую реализацию автоматически.
Размещайте варианты в выбранном наборе и задавайте фильтры так, чтобы нужная реализация оставалась в сборке.

## Практические рекомендации

- **Учитывайте короткую жизнь окна.** Сохраняйте данные при действии пользователя, а длительные задачи передавайте фоновому контексту.
- **Начинайте с готового интерфейса или состояния загрузки.** Загружайте данные асинхронно после синхронного `render` и показывайте ошибки.
- **Держите интерфейс компактным.** Задайте ширину и перенос длинных строк; проверьте размеры в целевых браузерах.
- **Запрашивайте доступ под задачу.** Для данных вкладки после нажатия кнопки используйте `activeTab`, если постоянный доступ не требуется.
- **Явно выбирайте начальный Popup.** При нескольких интерфейсах включите `multiplePopup` и оставьте `apply: true` только у нужного варианта.
- **Переключайте по алиасу.** Используйте `changePopup`, чтобы не привязывать код к пути HTML; учитывайте, что изменение видно при следующем открытии.

## Отладка

1. **Popup не появился в сборке.** Проверьте имя файла, размещение, фильтры и выбранный набор приложения или shared-слоя. При наличии файлов в `popups/` верхний уровень не используется. Убедитесь, что нужный HTML существует в сборке.
2. **Нажатие кнопки не открывает окно.** Проверьте `action.default_popup` или `browser_action.default_popup`, значение `apply` и путь HTML. Заново загрузите расширение после сборки; проверьте, не изменил ли другой код Popup для активной вкладки.
3. **Открылся другой интерфейс или не найден алиас.** Проверьте `multiplePopup`, фильтры и содержимое `getPopups()`. При одном Popup выбирается последний кандидат по приоритету; при нескольких начальным становится первый с разрешённым `apply`.
4. **Не вызывается обработчик нажатия кнопки расширения.** При назначенном Popup браузер не отправляет `action.onClicked` / `browserAction.onClicked`. Перенесите действие в обработчик внутри Popup или уберите назначение Popup, если нужен только обработчик кнопки расширения.
5. **Окно открылось без содержимого.** Проверьте результат `render` и консоль самого Popup. Для Vanilla нужны DOM-элемент, непустая строка или число; для React — файл `.tsx` / `.jsx` и установленные зависимости.
6. **HTML-теги видны как текст.** Строка из `render` отображается буквально. Создайте DOM-элементы или используйте JSX либо шаблон для разметки.
7. **Состояние сбрасывается после закрытия.** Это новый документ при каждом открытии. Проверьте, что нужные данные записываются в хранилище, а не только в переменную или состояние React.
8. **Переключение не изменило открытое окно.** Закройте и откройте Popup снова. Проверьте второй аргумент `changePopup`: настройка отдельной вкладки может перекрывать общее значение.
9. **Нет адреса вкладки или браузерный API блокируется.** Проверьте разрешения собранного Popup в итоговом манифесте, временный доступ `activeTab` и ограничения текущей страницы. После изменения разрешений заново загрузите расширение.
10. **Не загружается CSS, скрипт или ресурс.** Проверьте наличие файла в сборке, путь в `links`, `scripts` или `tags` и CSP. Готовые ресурсы поместите в `src/public`; путь `template` проверяйте относительно точки входа.
11. **Подсказка кнопки не изменилась или оказалась пустой.** Задайте `tooltip`, а не `title`: без `tooltip` переключение сохраняет прежнюю подсказку. Для ключа локализации проверьте сообщение в собранных `_locales` и язык браузера; пустой или не найденный браузером перевод при переключении передаётся как пустая строка.

Открывайте инструменты разработчика именно для окна Popup, например через **Inspect / Исследовать** в его контекстном меню.
Консоль background относится к другому контексту и не показывает все ошибки интерфейса.
