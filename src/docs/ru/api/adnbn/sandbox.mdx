Функции и типы для объявления изолированного HTML-документа и вызова его API через скрытый iframe. Все экспорты этой страницы доступны из `adnbn`. Использование, организация файлов и жизненный цикл относятся к [руководству Sandbox](/guide/entrypoints/sandbox).

Классы регистрации и proxy описаны в [`adnbn/sandbox`](/api/sandbox/index). Общие контракты транспорта — в [`adnbn/transport`](/api/transport/index), содержимое документа и HTML-опции — в [API отображения страниц](/api/adnbn/view).

## `defineSandbox`

<PropertyBadge text="function" type="info" outline />

Принимает объявление точки входа Sandbox.

```ts file="../../../../code/api/adnbn/sandbox/contracts/define-sandbox.ts" title="defineSandbox"
```

**Параметр:** `options` — [`SandboxDefinition<T>`](#sandboxdefinition). **Обязательный параметр.** В объекте нужен `init`; остальные поля можно опустить.

**Параметр типа:** `T extends TransportType` — API, который создаёт фабрика. [`TransportType`](/api/transport/index#transporttype) допускает объект, экземпляр класса или функцию. Обычно `T` выводится по результату `init`.

**Результат:** тот же объект `SandboxDefinition<T>` без копирования и подстановки значений по умолчанию. Функция не создаёт iframe и не вызывает обработчики.

## `getSandbox`

<PropertyBadge text="function" type="info" outline />

Возвращает асинхронный proxy для API Sandbox.

```ts file="../../../../code/api/adnbn/sandbox/contracts/get-sandbox.ts" title="getSandbox"
```

**Параметр:** `name` — [`SandboxName`](/api/sandbox/index#sandboxname). **Обязательный параметр.** Имя включённого в сборку Sandbox. `N` выбирает его контракт из реестра.

**Результат:** [`SandboxProxyTarget<N>`](/api/sandbox/index#sandboxproxytarget). Само получение proxy синхронное. При первом вызове через него Addon Bone создаёт скрытый iframe и ждёт сигнала готовности после `init`, `main` и отрисовки документа.

Повторные вызовы одного имени в текущей странице используют тот же iframe и экземпляр API. Параллельные первые вызовы ожидают общее создание. У разных страниц расширения свои iframe и состояние. После удаления iframe следующий вызов создаёт документ заново.

Вызывайте API из страницы расширения с готовым `document.body`, например popup, Page или Offscreen. В service worker нет DOM: получение proxy возможно, но вызов отклонится с `A frame can be created only from a page with DOM access.`. Для фоновой работы можно обращаться к Sandbox из [Offscreen](/api/adnbn/offscreen).

**Ошибки:** неизвестное имя синхронно вызывает `Unable to get sandbox: …`. Ошибка загрузки iframe, истечение [`readyTimeout`](#sandboxconfig-readytimeout) или [`requestTimeout`](#sandboxconfig-requesttimeout), а также исключение удалённого метода отклоняют promise вызова. Ошибка метода передаётся с именем, сообщением и доступным стеком. Обрабатывайте вызов через `try` / `catch`.

<DocHeading level={3} id="getsandbox-data" toc={false}>Данные и граница изоляции</DocHeading>

Методы и чтение простых свойств используют `await`, как описано в [`RpcAsyncProxy`](/api/transport/index#rpcasyncproxy). Здесь сообщения проходят через `window.postMessage`: аргументы и результаты должны поддерживать [структурированное клонирование](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage#parameters). Функции и DOM-узлы передавать нельзя; методы и прототипы экземпляров классов не становятся удалёнными объектами. Для обычных контрактов удобно возвращать данные из методов.

Sandbox-страница в Chrome не получает extension API и прямой доступ к другим страницам расширения. Обмен с владельцем iframe идёт через сообщения; это [модель sandbox в Chrome](https://developer.chrome.com/docs/extensions/reference/manifest/sandbox).

:::warning Ограничение текущей сборки для Firefox
Addon Bone не записывает `sandbox.pages` и sandbox CSP в манифест Firefox. Создаваемый runtime iframe не получает отдельный атрибут `sandbox`, поэтому его нельзя считать изолированной sandbox-страницей. Исключайте такую точку входа через [`excludeBrowser`](/api/adnbn/entrypoint-options#entrypointoptions-excludebrowser) для `"firefox"`, если задача требует этой изоляции или sandbox CSP.
:::

## `getSandboxes`

<PropertyBadge text="function" type="info" outline />

Читает таблицу Sandbox-документов текущей сборки.

```ts file="../../../../code/api/adnbn/sandbox/contracts/get-sandboxes.ts" title="getSandboxes"
```

**Параметры:** отсутствуют. **Результат:** [`SandboxMap`](#sandboxmap) с итоговыми именами и [`SandboxParameters`](#sandboxparameters).

В карту входят документы, прошедшие фильтры сборки, независимо от того, созданы ли их iframe. Функция не проверяет загрузку и готовность документов.

Каждый вызов возвращает новый `Map`, но вложенные объекты параметров не копируются. Изменение состава карты не меняет таблицу сборки. Настройки документа задавайте в объявлении, а не изменением общего объекта параметров.

Если чтение таблицы завершается ошибкой, функция пишет `Failed getting sandboxes:` в консоль и возвращает уже заполненную часть карты, возможно пустую.

## `SandboxDefinition`

<PropertyBadge text="interface" type="info" outline />

Объединяет фабрику API, опции Sandbox и содержимое документа.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-definition.ts" title="SandboxDefinition"
```

[`TransportDefinition`](/api/transport/index#transportdefinition) задаёт `init` и общий `main`; [`SandboxEntrypointOptions`](#sandboxentrypointoptions) — настройки документа; [`ViewRenderDefinition`](/api/adnbn/view#viewrenderdefinition) — `render` и `container`. Собственное поле интерфейса уточняет тип `main`.

<DocHeading level={3} id="sandboxdefinition-init" toc={true}>`init`</DocHeading>

**Тип:** [`TransportInitGetter<SandboxOptions, T>`](/api/transport/index#transportinitgetter). **Обязательное поле.** Унаследовано от `TransportDefinition`.

Синхронно создаёт API типа `T` внутри iframe. Получает [`SandboxOptions`](#sandboxoptions) с итоговым `name`, без `init`, `main`, `render` и `container`. Прочие опции сохраняют заданные значения: runtime-значения тайм-аутов по умолчанию в аргумент не подставляются.

Addon Bone регистрирует результат до вызова `main`. Не делайте фабрику `async`: её promise не ожидается. Асинхронную подготовку выполняйте в `main` или методах API. Если `init` выбрасывает исключение, регистрация и отрисовка не выполняются, сигнал готовности не отправляется; в консоли документа появляется `Failed to build sandbox:`.

<DocHeading level={3} id="sandboxdefinition-main" toc={true}>`main`</DocHeading>

**Тип:** [`SandboxMainHandler<T>`](#sandboxmainhandler). При отсутствии обработчик не вызывается.

Получает зарегистрированный API и тот же объект опций, что и `init`. Вызовы экземпляра здесь прямые; синхронные методы не превращаются в promise. Addon Bone ожидает завершения `main`, затем отображает документ и отправляет владельцу iframe сигнал готовности.

Если `main` выбрасывает исключение или возвращает отклонённый promise, отрисовка и сигнал готовности не выполняются. Ошибка выводится с `Failed to build sandbox:`; ожидающий iframe вызов может завершиться по `readyTimeout`. Регистрация к этому моменту уже существует.

<DocHeading level={3} id="sandboxdefinition-view" toc={false}>Содержимое документа</DocHeading>

[`render`](/api/adnbn/view#viewrenderdefinition-render) и [`container`](/api/adnbn/view#viewrenderdefinition-container) получают опции отображения без `init`, `main` и имени API `name`. Отрисовка начинается после завершения `main`, поэтому её DOM ещё недоступен в `init` и `main`. Для объявления транспорта обязателен `init`, даже когда задан `render`.

## `SandboxMainHandler`

<PropertyBadge text="type" type="info" outline />

Обработчик запуска зарегистрированного API.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-main-handler.ts" title="SandboxMainHandler"
```

**Параметры:** `sandbox` — экземпляр `T extends` [`TransportType`](/api/transport/index#transporttype); `options` — [`SandboxEntrypointOptions`](#sandboxentrypointoptions).

**Результат:** `Awaiter<void>`, то есть `void | Promise<void>`. `Awaiter<T>` — внутренний вспомогательный алиас, не отдельный экспорт `adnbn`. Условия вызова и ошибки описаны у [`main`](#sandboxdefinition-main).

## `SandboxConfig`

<PropertyBadge text="interface" type="info" outline />

Имя API и параметры ожидания iframe и ответа.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-config.ts" title="SandboxConfig"
```

Наследует `name` из внутреннего [`TransportConfig`](/api/transport/index#transportconfig). При использовании самого `SandboxConfig` имя обязательно; [`SandboxEntrypointOptions`](#sandboxentrypointoptions) делает его необязательным в объявлении.

<DocHeading level={3} id="sandboxconfig-name" toc={true}>`name`</DocHeading>

**Тип:** `string`. **Обязательное поле в `SandboxConfig`.** В `SandboxDefinition` можно опустить: сборщик выводит имя из пути файла.

Явное имя после удаления пробелов по краям должно содержать от 1 до 100 символов. Первый символ — буква Unicode, `_` или `$`; далее допустимы также цифры. Сборщик разрешает совпадения локальных имён добавлением числового суффикса. Используйте итоговые имена из [`SandboxRegistry`](/api/sandbox/index#sandboxregistry) или [`getSandboxes`](#getsandboxes).

Имя API не задаёт имя HTML-файла: для него есть [`as`](/api/adnbn/view#viewconfig-as).

<DocHeading level={3} id="sandboxconfig-readytimeout" toc={true}>`readyTimeout`</DocHeading>

**Тип:** `number`. **По умолчанию:** `10000` миллисекунд. В объявлении допустимо положительное число.

Сколько ждать сигнал готовности при создании iframe. Отсчёт включает загрузку, `init`, ожидание `main` и отрисовку. События `load` недостаточно. При превышении времени запрос отклоняется, неготовый iframe удаляется; следующий вызов может создать новый.

<DocHeading level={3} id="sandboxconfig-requesttimeout" toc={true}>`requestTimeout`</DocHeading>

**Тип:** `number`. **По умолчанию:** `30000` миллисекунд. В объявлении допустимо положительное число.

Сколько ждать ответ на отдельный запрос после готовности iframe. Ожидание загрузки сюда не входит. По истечении времени promise отклоняется с `Sandbox "…" request "…" timed out.`. Поздний ответ игнорируется. Сам таймер не отменяет выполнение метода внутри документа.

<DocHeading level={3} id="sandboxconfig-removeonrequesttimeout" toc={true}>`removeOnRequestTimeout`</DocHeading>

**Тип:** `boolean`. **По умолчанию:** iframe сохраняется.

При `true` тайм-аут запроса удаляет iframe и его канал, только если у этого Sandbox больше нет ожидающих ответов. Следующий вызов создаёт новый документ, поэтому его состояние будет потеряно. При `false` или отсутствии поля тайм-аут не удаляет готовый iframe.

Проверка выполняется именно при тайм-ауте: если в этот момент ещё есть запросы, последующее успешное завершение остальных само по себе не удалит документ.

## `SandboxCspOptions`

<PropertyBadge text="interface" type="info" outline />

Поле CSP в объявлении Sandbox.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-csp-options.ts" title="SandboxCspOptions"
```



<DocHeading level={3} id="sandboxcspoptions-csp" toc={true}>`csp`</DocHeading>

**Тип:** [`SandboxCspConfig`](#sandboxcspconfig).

Добавляет настройки в общую политику sandbox-страниц расширения. Она применяется ко всем путям `sandbox.pages`, а не только к документу, который задал объект. Политика обычных страниц из [`CspOptions`](/api/adnbn/csp#cspoptions) собирается отдельно.

Если поле отсутствует, объявление не добавляет свою CSP. Если других настроек sandbox CSP нет, соответствующее поле манифеста отсутствует и браузер использует свою политику по умолчанию. Пустой объект `{}` включает генерацию с настройками Addon Bone: `eval: true`, `inline: false`, без дополнительных `allow`, с `child-src 'self'`.

Во всех примерах ниже `src/sandbox.ts` объявляет точку входа через [`defineSandbox`](#definesandbox). При стандартном [`htmlDir`](/api/adnbn/configuration#config-htmldir) Addon Bone создаёт `sandbox.html`, добавляет его в `sandbox.pages` и собирает политику из поля `csp`. Обязательная фабрика `init` возвращает пустой API: примеры показывают только настройку CSP.

Каждый пример используется отдельно, без других Sandbox-объявлений. Во вкладках результата показаны относящиеся к Sandbox фрагменты манифеста Chromium. Для Firefox эти поля генератор опускает.

## `SandboxCspConfig`

<PropertyBadge text="interface" type="info" outline />

Настройки общей политики sandbox-документов.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-csp-config.ts" title="SandboxCspConfig"
```

Addon Bone всегда добавляет `sandbox allow-scripts`, `script-src 'self'` и источник `'self'` для `child-src`. `allow-same-origin` не поддерживается: [контракт Chrome](https://developer.chrome.com/docs/extensions/reference/manifest/sandbox) запрещает его для sandbox-страниц.

Настройки включённых объявлений объединяются. `eval` и `inline` включаются, если хотя бы один объект разрешает их; последующий `false` не отменяет `true`. Значения `allow` и списки источников объединяются без повторов.

В Manifest V3 результат находится в `content_security_policy.sandbox`, в V2 — в `sandbox.content_security_policy`. Можно передать этот же объект в [`ManifestBuilder.addSandboxCsp`](/api/adnbn/manifest#manifestbuilder-addsandboxcsp). Структурированная sandbox-политика имеет приоритет над сырым значением sandbox CSP; строка всего `content_security_policy` в V3 несовместима с её структурированной генерацией.

<DocHeading level={3} id="sandboxcspconfig-eval" toc={true}>`eval`</DocHeading>

**Тип:** `boolean`. **По умолчанию в переданном объекте CSP:** `true`.

## `SandboxAllow`

<PropertyBadge text="enum" type="info" outline />

Дополнительные разрешения директивы sandbox.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-allow.ts" title="SandboxAllow"
```

Используется в [`SandboxCspConfig.allow`](#sandboxcspconfig-allow). Принимаются члены enum или точные строковые значения без `allow-`; префикс добавляет генератор.

| Член | Результат в CSP | Назначение |
| --- | --- | --- |
| `Forms` | `allow-forms` | Отправка форм. |
| `Popups` | `allow-popups` | Открытие новых окон. |
| `Modals` | `allow-modals` | Модальные вызовы, например `alert` и `confirm`. |
| `Downloads` | `allow-downloads` | Загрузка файлов. |
| `PointerLock` | `allow-pointer-lock` | Захват указателя через Pointer Lock API. |
| `TopNavigationByUserActivation` | `allow-top-navigation-by-user-activation` | Навигация верхнего контекста после действия пользователя. |

Флаги снимают соответствующие ограничения sandbox, но не отменяют другие правила браузера. Подробные условия — в [директиве `sandbox` на MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox).

## `SandboxSource`

<PropertyBadge text="enum" type="info" outline />

Поддерживаемые ключевые слова и схемы источников.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-source.ts" title="SandboxSource"
```

Используется в [`SandboxCspSources`](#sandboxcspsources).

| Член | Значение | Назначение |
| --- | --- | --- |
| `Self` | `"'self'"` | Собственные ресурсы, разрешённые этой CSP. |
| `None` | `"'none'"` | Запрет источников для директивы. |
| `Data` | `"data:"` | Ресурсы `data:`. |
| `Blob` | `"blob:"` | Ресурсы `blob:`. |
| `UnsafeInline` | `"'unsafe-inline'"` | Встроенные стили в `sources.style`. |

Для строковых ключевых слов сохраняйте внутренние одинарные кавычки: `"'self'"`, а не `"self"`. Для встроенных скриптов используйте [`inline`](#sandboxcspconfig-inline). `None` задавайте отдельно: добавление других источников не означает их запрет. <DocHeading level={3} id="sandboxresponsemessage-requestid" toc={true}>`requestId`</DocHeading>

**Тип:** `string`. **Обязательное поле.** Идентификатор исходного запроса.

<DocHeading level={3} id="sandboxresponsemessage-ok" toc={true}>`ok`</DocHeading>

**Тип:** `boolean`. **Обязательное поле.** `true` для результата, `false` для ошибки.

<DocHeading level={3} id="sandboxresponsemessage-payload" toc={true}>`payload`</DocHeading>

**Тип:** `any`. Результат при `ok: true`; может быть `undefined`.

<DocHeading level={3} id="sandboxresponsemessage-error" toc={true}>`error`</DocHeading>

**Тип:** `MessageError`. Объект `{name: string; message: string; stack?: string}` при `ok: false`. Это вспомогательный контракт сообщений; в импорт `adnbn/sandbox` он не входит.

## `SandboxPort`

<PropertyBadge text="interface" type="info" outline />

Контракт подключения, отправки и получения сообщений.

```ts file="../../../../code/api/adnbn/sandbox/contracts/sandbox-port.ts" title="SandboxPort"
```

Расположен под протоколом запросов и ответов. Встроенные реализации работают с родительской страницей и iframe. `ProxySandbox` и `RegisterSandbox` выбирают их самостоятельно и не принимают пользовательский порт в конструкторе.

<DocHeading level={3} id="sandboxport-connect" toc={true}>`connect`</DocHeading>

**Сигнатура:** `connect(): Promise<void>`. **Обязательный метод.** Подготавливает канал. На стороне владельца создаёт iframe и ожидает готовности; повторные и параллельные подключения используют общее создание. Внутри Sandbox разрешается сразу.

<DocHeading level={3} id="sandboxport-post" toc={true}>`post`</DocHeading>

**Сигнатура:** `post(message: SandboxEnvelope): void`. **Обязательный метод.** Передаёт готовый [`SandboxEnvelope`](#sandboxenvelope) другой стороне. Сам метод не ждёт ответа; корреляцию и тайм-ауты выполняет слой над портом.

<DocHeading level={3} id="sandboxport-subscribe" toc={true}>`subscribe`</DocHeading>

**Сигнатура:** `subscribe(onMessage: (message: SandboxEnvelope, sender: MessageSender) => void): () => void`. **Обязательный метод.** Подписывает обработчик и возвращает функцию снятия подписки.

`message` — [`SandboxEnvelope`](#sandboxenvelope). `MessageSender` — алиас `chrome.runtime.MessageSender`. Здесь runtime формирует только `url` и `origin` текущего документа на принимающей стороне; это не полный sender браузерного `runtime.onMessage` и не сведения о вкладке отправителя.

<DocHeading level={3} id="sandboxport-dispose" toc={true}>`dispose`</DocHeading>

**Сигнатура:** `dispose(): void`. **Обязательный метод.** Освобождает канал: снимает слушатель, а порт владельца также удаляет iframe. Этот контракт не является публичным методом уничтожения у `ProxySandbox`.
