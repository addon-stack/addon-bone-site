## `ManifestBuilder`

<PropertyBadge text="interface" type="info" outline />

Билдер, который Addon Bone передаёт в callback настройки [`manifest`](/api/adnbn/configuration#config-manifest) и обработчик `manifest` плагина. Это интерфейс TypeScript: его можно импортировать через `import type`, но нельзя вызвать или создать через `new`.

```ts file="../../../../code/api/adnbn/manifest/contracts/manifest-builder.ts" title="ManifestBuilder"
```

**Параметр типа:** `T extends CoreManifest = Manifest` — тип объекта, возвращаемого [`get()`](#manifestbuilder-get). [`CoreManifest`](#coremanifest) описывает базовые поля манифеста, а [`Manifest`](#manifest) объединяет варианты для Chrome, Firefox и Safari. Параметр `T` не выбирает версию сборки: её задаёт [`manifestVersion`](/api/adnbn/configuration#config-manifestversion).

**Результат методов:** все методы изменения возвращают `this`, поэтому вызовы можно объединять в цепочку. Они выполняются синхронно. Исключения по возвращаемому типу — `get()` и `getWebAccessibleResources()`.

**Аргументы:** каждый метод изменения принимает один аргумент. Если в сигнатуре нет `?`, аргумент обязателен. Коллекции `Set` и `Map` передаются именно как `Set` и `Map`; массив подходит только для параметров `Iterable` и полей, объявленных массивами.

<DocHeading level={3} id="manifestbuilder-order" toc={false}>Когда применяются изменения</DocHeading>

Обработчики `manifest` пользовательских плагинов выполняются перед встроенными. Встроенные обработчики заполняют настройки и точки входа, затем Addon Bone читает `manifest` из `package.json` и вызывает callback `manifest` из конфигурации. Поэтому callback может переопределить уже заполненное значение через `set…`. Результат callback, если это объект, добавляется через [`raw()`](#manifestbuilder-raw).

После компиляции Addon Bone связывает точки входа с выходными файлами, вызывает `get()` и записывает `manifest.json`. Карту зависимостей заполняет сама сборка: `setDependencies()` не входит в публичный `ManifestBuilder`, а `ManifestDependencies` и `ManifestDependency` не экспортируются из `adnbn`. Сам вызов метода билдера не создаёт точку входа, не компилирует исходник и не копирует ресурс.

В режиме `watch` для очередной компиляции создаётся новый билдер. Сохраняйте настройки в callback или обработчике плагина; не рассчитывайте на состояние экземпляра от предыдущей сборки.

<DocHeading level={3} id="manifestbuilder-setname" toc={true}>`setName`</DocHeading>

**Сигнатура:** `setName(name: string): this`.

Задаёт `name` — имя расширения. Непустая строка имеет приоритет над `name` из `raw`. При пустой строке билдер использует значение из `raw`, затем `"__MSG_app_name__"`. Обычная сборка заранее задаёт имя из конфигурации.

<DocHeading level={3} id="manifestbuilder-setshortname" toc={true}>`setShortName`</DocHeading>

**Сигнатура:** `setShortName(shortName?: string): this`.

Задаёт `short_name`. Пустая строка или вызов без аргумента снимает значение этого метода: тогда используется `short_name` из `raw`, а при его отсутствии поле не записывается.

<DocHeading level={3} id="manifestbuilder-setdescription" toc={true}>`setDescription`</DocHeading>

**Сигнатура:** `setDescription(description?: string): this`.

Задаёт `description`. При пустой строке или отсутствии аргумента используется описание из `raw`; если его тоже нет, поле отсутствует. Метод принимает готовый текст или строку манифеста вида `"__MSG_description__"`: он не преобразует ключи `@…` самостоятельно.

<DocHeading level={3} id="manifestbuilder-setauthor" toc={true}>`setAuthor`</DocHeading>

**Сигнатура:** `setAuthor(author?: string): this`.

Задаёт строку `author`. Пустая строка или отсутствие аргумента возвращает выбор к `author` из `raw`; без обоих значений поле отсутствует. Метод не читает переменную окружения по переданной строке.

<DocHeading level={3} id="manifestbuilder-sethomepage" toc={true}>`setHomepage`</DocHeading>

**Сигнатура:** `setHomepage(homepage?: string): this`.

Задаёт `homepage_url`. Передавайте готовый URL; сам метод не проверяет его и не читает `.env`. При пустой строке или отсутствии аргумента используется URL из `raw`, иначе поле отсутствует.

<DocHeading level={3} id="manifestbuilder-setversion" toc={true}>`setVersion`</DocHeading>

**Сигнатура:** `setVersion(version?: string): this`.

Задаёт `version` без преобразования строки через semver. Пустая строка или отсутствие аргумента выбирает `version` из `raw`, затем `"0.0.0"`. Дополнительная строка `version_name` задаётся через [`raw()`](#manifestbuilder-raw).

<DocHeading level={3} id="manifestbuilder-setincognito" toc={true}>`setIncognito`</DocHeading>

**Сигнатура:** `setIncognito(incognito?: ManifestIncognitoValue): this`.

Задаёт `incognito`. Тип [`ManifestIncognitoValue`](#manifestincognitovalue) допускает [`ManifestIncognito`](#manifestincognito) и строки `"spanning"`, `"split"`, `"not_allowed"`. Без аргумента используется значение из `raw`; если его нет, поле не записывается.

<DocHeading level={3} id="manifestbuilder-setminimumversion" toc={true}>`setMinimumVersion`</DocHeading>

**Сигнатура:** `setMinimumVersion(minimumVersion?: string): this`.

Задаёт `minimum_chrome_version` готовой строкой, без нормализации версии. При пустой строке или отсутствии аргумента используется значение из `raw`, иначе поле отсутствует. Ограничения версий Firefox и Safari задаются через [`setSpecific()`](#manifestbuilder-setspecific).

<DocHeading level={3} id="manifestbuilder-setlocale" toc={true}>`setLocale`</DocHeading>

**Сигнатура:** `setLocale(lang?: Language): this`.

Задаёт `default_locale`. Аргумент — значение перечисления `Language`, например `Language.English`. Без аргумента используется `default_locale` из `raw`, а при его отсутствии поле не записывается. Метод не создаёт файлы `_locales`; они должны существовать в результате сборки.

<DocHeading level={3} id="manifestbuilder-setspecific" toc={true}>`setSpecific`</DocHeading>

**Сигнатура:** `setSpecific(settings?: BrowserSpecific): this`.

Заменяет браузерные настройки билдера. Объект [`BrowserSpecific`](#browserspecific) содержит группы `gecko`, `geckoAndroid` и `safari`. Внутри этих групп используются поля в camelCase, например `strictMinVersion`.

Без аргумента снимает настройки, заданные этим методом. Данные из `browser_specific_settings`, переданные через `raw`, остаются отдельным источником. При генерации Addon Bone выбирает настройки целевого браузера и преобразует имена полей в формат манифеста.

<DocHeading level={3} id="manifestbuilder-mergespecific" toc={true}>`mergeSpecific`</DocHeading>

**Сигнатура:** `mergeSpecific(settings: BrowserSpecific): this`.

Дополняет текущие браузерные настройки: вложенные объекты объединяются, новые скалярные значения заменяют прежние, массивы объединяются без повторов. Пустой объект сохраняет текущие настройки. Принимает ту же форму, что [`setSpecific()`](#manifestbuilder-setspecific).

<DocHeading level={3} id="manifestbuilder-seticons" toc={true}>`setIcons`</DocHeading>

**Сигнатура:** `setIcons(icons?: ManifestIcons): this`.

Заменяет реестр групп иконок. Принимает [`ManifestIcons`](#manifesticons) — карту групп из [`ManifestIcon`](#manifesticon). Внешний ключ — имя группы, внутренний — размер, значение — путь к готовой иконке. Например, `new Map([["default", new Map([[16, "icons/16.png"]])]])` описывает одну группу с иконкой 16 × 16.

Пустая `Map` или отсутствие аргумента очищает реестр. Метод не копирует файлы; в обычной сборке реестр заполняет плагин иконок.

<DocHeading level={3} id="manifestbuilder-seticon" toc={true}>`setIcon`</DocHeading>

**Сигнатура:** `setIcon(icon?: string): this`.

Выбирает группу из [`setIcons()`](#manifestbuilder-seticons) для `manifest.icons` и запасной иконки кнопки. Без аргумента или при пустой строке выбирается `default`. Если указанной группы нет, используется `default`, затем первая доступная группа. Билдер выбирает одну группу целиком; недостающие размеры из других групп не добавляются.

В `manifest.icons` выбранная группа объединяется с полем `icons` из [`raw()`](#manifestbuilder-raw) по размерам. При совпадении размера путь из группы имеет приоритет, остальные размеры из `raw` сохраняются. При пустом реестре остаются только иконки из `raw`. Для иконки кнопки билдер использует реестр групп; поле `raw.icons` в этот выбор не входит.

<DocHeading level={3} id="manifestbuilder-setaction" toc={true}>`setAction`</DocHeading>

**Сигнатура:** `setAction(action?: ActionOptions): this`.

Задаёт [`ActionOptions`](/api/adnbn/configuration#actionoptions): группу `icon` и подсказку `title` кнопки. Даже `{}` объявляет кнопку без popup. В MV3 Addon Bone записывает `action`, в MV2 — `browser_action`.

Без аргумента снимает это объявление кнопки; popup или команда `_execute_action` всё ещё могут её добавить. Поля popup имеют приоритет над `ActionOptions`. Метод не создаёт обработчик нажатия.

<DocHeading level={3} id="manifestbuilder-setbackground" toc={true}>`setBackground`</DocHeading>

**Сигнатура:** `setBackground(background?: ManifestBackground): this`.

Задаёт фоновую точку сборки. Принимает [`ManifestBackground`](#manifestbackground). Его [`entry`](#manifestentry-entry) — имя существующей точки сборки, по которому Addon Bone находит выходные файлы.

Без аргумента снимает фоновую точку билдера. Для неё должна существовать непустая коллекция JS-зависимостей. В MV2 записываются `background.scripts` и заданное `persistent`, включая `false`. В MV3 для Firefox используются `scripts` без `persistent`; для остальных целей — `service_worker`, которому нужна ровно одна JS-зависимость. Нарушение этих условий вызывает ошибку при `get()`.

Поля разрешений из `BackgroundConfig` сам этот метод не добавляет: передавайте их методам разрешений. При работе через `defineBackground` это делает плагин фоновых точек входа.

<DocHeading level={3} id="manifestbuilder-setcommands" toc={true}>`setCommands`</DocHeading>

**Сигнатура:** `setCommands(commands?: ManifestCommands): this`.

Заменяет набор описаний команд. Принимает [`ManifestCommands`](#manifestcommands) — набор [`ManifestCommand`](#manifestcommand). У каждого описания обязателен `name`; `description`, `global` и клавиши `defaultKey`, `windowsKey`, `macKey`, `chromeosKey`, `linuxKey` можно опустить.

Без аргумента или с пустым `Set` снимает этот набор, но сохраняет команды из `raw`. Команды объединяются по имени; поля билдера имеют приоритет. Без описания используется имя команды, кроме `_execute_action`. В MV2 `_execute_action` преобразуется в `_execute_browser_action`. Метод описывает команды в манифесте, но не регистрирует обработчики и не добавляет разрешения из их конфигурации.

<DocHeading level={3} id="manifestbuilder-setcontentscripts" toc={true}>`setContentScripts`</DocHeading>

**Сигнатура:** `setContentScripts(contentScripts?: ManifestContentScripts): this`.

Заменяет набор content script. Принимает [`ManifestContentScripts`](#manifestcontentscripts) — набор [`ManifestContentScript`](#manifestcontentscript).

Обязательный `entry` выбирает JS и CSS из карты зависимостей. Поля `matches`, `excludeMatches`, `allFrames`, `runAt`, `includeGlobs`, `excludeGlobs`, `matchAboutBlank`, `matchOriginAsFallback` и `world` преобразуются в поля `content_scripts`. В MV2 `world` и `match_origin_as_fallback` не записываются.

Без аргумента или с пустым `Set` очищает только этот набор; описания из `raw` остаются. При неизвестном `entry` или отсутствии у него и JS, и CSS `get()` вызывает ошибку. Метод не создаёт исходные файлы и не применяет фильтры включения точек входа.

<DocHeading level={3} id="manifestbuilder-setpopup" toc={true}>`setPopup`</DocHeading>

**Сигнатура:** `setPopup(popup?: ManifestPopup): this`.

Задаёт popup кнопки. Принимает [`ManifestPopup`](#manifestpopup): путь к готовому HTML, группу иконок и подсказку кнопки.

`path` становится `default_popup`. [`title`](#manifestpopup-title) задаёт подсказку кнопки: в MV3 это `action.default_title`, в MV2 — `browser_action.default_title`. Для `icon` и `title` пропущенные значения берутся из [`setAction()`](#manifestbuilder-setaction), затем из общей группы [`setIcon()`](#manifestbuilder-seticon) и имени, заданного через [`setName()`](#manifestbuilder-setname). Пустой `title` сохраняется. `{}` объявляет кнопку без пути к popup; вызов без аргумента снимает popup билдера.

<DocHeading level={3} id="manifestbuilder-setsidebar" toc={true}>`setSidebar`</DocHeading>

**Сигнатура:** `setSidebar(sidebar?: ManifestSidebar): this`.

Задаёт боковую панель через [`ManifestSidebar`](#manifestsidebar): путь к готовому HTML, группу иконок и заголовок панели.

Для Firefox и Opera Addon Bone формирует `sidebar_action`, для остальных целей в MV3 — `side_panel`. В MV2 для остальных целей поле не добавляется. Без аргумента билдер использует подходящее поле из `raw`, если оно есть. Метод не создаёт страницу и не добавляет разрешение `sidePanel` автоматически.

<DocHeading level={3} id="manifestbuilder-setoptions" toc={true}>`setOptions`</DocHeading>

**Сигнатура:** `setOptions(options?: ManifestOptions): this`.

Задаёт `options_ui`. Принимает [`ManifestOptions`](#manifestoptions): путь к готовому HTML и режим открытия. Если `openInTab` опущен, записывается `open_in_tab: true`; `false` сохраняется.

Без аргумента снимает это описание страницы; `options_ui` и `options_page` из `raw` остаются доступными. Метод не создаёт HTML-файл.

<DocHeading level={3} id="manifestbuilder-setoverride" toc={true}>`setOverride`</DocHeading>

**Сигнатура:** `setOverride(override?: ManifestOverride): this`.

Задаёт одну замену страницы браузера. Принимает [`ManifestOverride`](#manifestoverride) с обязательными полями `page` и `path`. Результат — `chrome_url_overrides` с одной парой `page: path`; путь относится к готовому HTML в расширении.

Без аргумента снимает значение метода и использует `chrome_url_overrides` из `raw`, если оно есть. Этот метод не проверяет поддержку выбранной страницы целевым браузером и не создаёт HTML-файл.

<DocHeading level={3} id="manifestbuilder-addsandbox" toc={true}>`addSandbox`</DocHeading>

**Сигнатура:** `addSandbox(sandbox: ManifestSandbox): this`.

Добавляет путь готовой sandbox-страницы. Принимает [`ManifestSandbox`](#manifestsandbox) — строку пути. Путь объединяется с `sandbox.pages` из `raw`; одинаковые строки не дублируются. Для Firefox Addon Bone не выводит секцию `sandbox`.

<DocHeading level={3} id="manifestbuilder-appendsandboxes" toc={true}>`appendSandboxes`</DocHeading>

**Сигнатура:** `appendSandboxes(sandboxes: Iterable<ManifestSandbox>): this`.

Добавляет несколько путей по правилам [`addSandbox()`](#manifestbuilder-addsandbox). Подходит массив или `Set<string>`. Пустая коллекция ничего не меняет.

<DocHeading level={3} id="manifestbuilder-addsandboxcsp" toc={true}>`addSandboxCsp`</DocHeading>

**Сигнатура:** `addSandboxCsp(csp: SandboxCspConfig): this`.

Добавляет настройки CSP sandbox: `eval`, `inline`, `allow` и `sources` из [`SandboxCspConfig`](/api/adnbn/sandbox#sandboxcspconfig). Настройки накапливаются вместе с другими объявлениями sandbox CSP; вызов не добавляет саму страницу в `sandbox.pages`.

В MV2 политика записывается в `sandbox.content_security_policy`, в MV3 — в `content_security_policy.sandbox`. Для Firefox Addon Bone не выводит sandbox CSP. Если есть и собранная sandbox-политика, и её сырое значение, используется собранная политика.

<DocHeading level={3} id="manifestbuilder-appendsandboxcsp" toc={true}>`appendSandboxCsp`</DocHeading>

**Сигнатура:** `appendSandboxCsp(csps: Iterable<SandboxCspConfig>): this`.

Последовательно добавляет настройки через [`addSandboxCsp()`](#manifestbuilder-addsandboxcsp). Принимает массив или другую итерируемую коллекцию; пустая коллекция ничего не меняет.

<DocHeading level={3} id="manifestbuilder-addcsp" toc={true}>`addCsp`</DocHeading>

**Сигнатура:** `addCsp(csp: CspConfig): this`.

Добавляет настройки CSP страниц расширения. Принимает [`CspConfig`](/api/adnbn/csp#cspconfig): [`wasm`](/api/adnbn/csp#cspconfig-wasm) разрешает WebAssembly, а [`sources`](/api/adnbn/csp#cspsources) задаёт источники ресурсов. Правила объединения и значения источников описаны в этих контрактах.

В MV2 политика выводится строкой `content_security_policy`, в MV3 — полем `content_security_policy.extension_pages`. Если одновременно задана собранная политика и сырая политика страниц расширения через `raw`, `get()` завершается ошибкой: выберите один способ задания этой политики.

<DocHeading level={3} id="manifestbuilder-appendcsp" toc={true}>`appendCsp`</DocHeading>

**Сигнатура:** `appendCsp(csps: Iterable<CspConfig>): this`.

Принимает итерируемую коллекцию [`CspConfig`](/api/adnbn/csp#cspconfig) и последовательно добавляет настройки через [`addCsp()`](#manifestbuilder-addcsp). Пустая коллекция ничего не меняет; ранее добавленные настройки сохраняются.

<DocHeading level={3} id="manifestbuilder-addpermission" toc={true}>`addPermission`</DocHeading>

**Сигнатура:** `addPermission(permission: ManifestPermission): this`.

Добавляет одно разрешение браузерного API, например `"storage"`. Тип [`ManifestPermission`](#manifestpermission) использует `chrome.runtime.ManifestPermission`. Повторное добавление той же строки не создаёт дубль. Для адресов сайтов используйте [`addHostPermission()`](#manifestbuilder-addhostpermission).

При генерации билдер объединяет этот набор с `permissions` из `raw` и адаптирует его к версии манифеста:

| Условие | Действие Addon Bone |
| --- | --- |
| Есть `tabs` | Удаляет `activeTab`. |
| Manifest V2 | Заменяет `scripting` на `tabs` и удаляет `offscreen`. |
| Manifest V3 | Удаляет `webAuthenticationProxy`, `webRequestAuthProvider` и `webRequestBlocking`. |

Это правила текущего генератора Addon Bone; они не являются полным списком возможностей браузера.

<DocHeading level={3} id="manifestbuilder-setpermissions" toc={true}>`setPermissions`</DocHeading>

**Сигнатура:** `setPermissions(permissions: ManifestPermissions): this`.

Заменяет накопленный набор API-разрешений. Принимает [`ManifestPermissions`](#manifestpermissions) — `Set` разрешений. `new Set()` очищает этот набор, но не удаляет разрешения из `raw`. К результату применяются правила [`addPermission()`](#manifestbuilder-addpermission).

<DocHeading level={3} id="manifestbuilder-appendpermissions" toc={true}>`appendPermissions`</DocHeading>

**Сигнатура:** `appendPermissions(permissions: ManifestPermissions): this`.

Добавляет разрешения из [`ManifestPermissions`](#manifestpermissions), сохраняя прежние. Пустой `Set` ничего не меняет. Например, callback ниже добавляет два API-разрешения, отдельное необязательное разрешение и доступ к сайту:

```ts file="../../../../code/api/adnbn/manifest/examples/permissions.config.ts" title="adnbn.config.ts"
```

<DocHeading level={3} id="manifestbuilder-addoptionalpermission" toc={true}>`addOptionalPermission`</DocHeading>

**Сигнатура:** `addOptionalPermission(permission: ManifestOptionalPermission): this`.

Добавляет разрешение в `optional_permissions`. Тип [`ManifestOptionalPermission`](#manifestoptionalpermission) основан на `chrome.runtime.ManifestOptionalPermission`. Одинаковые разрешения не дублируются; разрешение, уже вошедшее в обязательные, не записывается как необязательное. Применяются те же преобразования для версии манифеста, что у [`addPermission()`](#manifestbuilder-addpermission).

Объявление не выдаёт доступ: расширение запрашивает необязательное разрешение отдельно через Permissions API.

<DocHeading level={3} id="manifestbuilder-setoptionalpermissions" toc={true}>`setOptionalPermissions`</DocHeading>

**Сигнатура:** `setOptionalPermissions(permissions: ManifestOptionalPermissions): this`.

Заменяет набор необязательных API-разрешений. Принимает [`ManifestOptionalPermissions`](#manifestoptionalpermissions). Пустой `Set` очищает этот набор; данные `optional_permissions`, переданные через `raw`, сохраняются.

<DocHeading level={3} id="manifestbuilder-appendoptionalpermissions" toc={true}>`appendOptionalPermissions`</DocHeading>

**Сигнатура:** `appendOptionalPermissions(permissions: ManifestOptionalPermissions): this`.

Добавляет разрешения из [`ManifestOptionalPermissions`](#manifestoptionalpermissions) к текущему набору. Пустой `Set` ничего не меняет. Итоговый список формируется по правилам [`addOptionalPermission()`](#manifestbuilder-addoptionalpermission).

<DocHeading level={3} id="manifestbuilder-addhostpermission" toc={true}>`addHostPermission`</DocHeading>

**Сигнатура:** `addHostPermission(permission: string): this`.

Добавляет шаблон доступа к сайту, например `"https://example.com/*"`. В MV3 шаблоны записываются в `host_permissions`, в MV2 — в `permissions`. Билдер объединяет их с `host_permissions` из `raw`, удаляет повторы и более узкие шаблоны, покрытые широкими.

<DocHeading level={3} id="manifestbuilder-sethostpermissions" toc={true}>`setHostPermissions`</DocHeading>

**Сигнатура:** `setHostPermissions(permissions: ManifestHostPermissions): this`.

Заменяет набор шаблонов сайтов. Принимает [`ManifestHostPermissions`](#manifesthostpermissions) — `Set<string>`. Пустой `Set` очищает этот набор, сохраняя шаблоны из `raw`. Формат результата зависит от версии манифеста, как у [`addHostPermission()`](#manifestbuilder-addhostpermission).

<DocHeading level={3} id="manifestbuilder-appendhostpermissions" toc={true}>`appendHostPermissions`</DocHeading>

**Сигнатура:** `appendHostPermissions(permissions: ManifestHostPermissions): this`.

Добавляет шаблоны из [`ManifestHostPermissions`](#manifesthostpermissions), сохраняя текущие. Пустой `Set` ничего не меняет.

<DocHeading level={3} id="manifestbuilder-addoptionalhostpermission" toc={true}>`addOptionalHostPermission`</DocHeading>

**Сигнатура:** `addOptionalHostPermission(permission: string): this`.

Добавляет необязательный доступ к сайту. В MV3 результат попадает в `optional_host_permissions`, в MV2 — в `optional_permissions`. Шаблоны объединяются с необязательными host-разрешениями из `raw`; доступ, покрытый обязательными host-разрешениями, исключается из необязательного списка.

<DocHeading level={3} id="manifestbuilder-setoptionalhostpermissions" toc={true}>`setOptionalHostPermissions`</DocHeading>

**Сигнатура:** `setOptionalHostPermissions(permissions: ManifestHostPermissions): this`.

Заменяет набор необязательных шаблонов сайтов. Принимает [`ManifestHostPermissions`](#manifesthostpermissions). Пустой `Set` очищает этот набор, но не данные `optional_host_permissions`, переданные через `raw`.

<DocHeading level={3} id="manifestbuilder-appendoptionalhostpermissions" toc={true}>`appendOptionalHostPermissions`</DocHeading>

**Сигнатура:** `appendOptionalHostPermissions(permissions: ManifestHostPermissions): this`.

Добавляет шаблоны из [`ManifestHostPermissions`](#manifesthostpermissions) по правилам [`addOptionalHostPermission()`](#manifestbuilder-addoptionalhostpermission). Пустой `Set` ничего не меняет.

<DocHeading level={3} id="manifestbuilder-setaccessibleresource" toc={true}>`setAccessibleResource`</DocHeading>

**Сигнатура:** `setAccessibleResource(accessibleResources: ManifestAccessibleResources): this`.

Заменяет явно заданный набор web-accessible ресурсов. Несмотря на единственное число в имени метода, аргумент — коллекция [`ManifestAccessibleResources`](#manifestaccessibleresources).

Пустой `Set` очищает этот набор, но ресурсы из `raw` и зависимостей content script остаются. Форма одного правила описана у [`addAccessibleResource()`](#manifestbuilder-addaccessibleresource).

<DocHeading level={3} id="manifestbuilder-appendaccessibleresources" toc={true}>`appendAccessibleResources`</DocHeading>

**Сигнатура:** `appendAccessibleResources(accessibleResources: ManifestAccessibleResources): this`.

Добавляет правила из `Set` с элементами [`ManifestAccessibleResource`](#manifestaccessibleresource), сохраняя текущие. Пустой `Set` ничего не меняет. Итоговое объединение выполняет [`getWebAccessibleResources()`](#manifestbuilder-getwebaccessibleresources).

<DocHeading level={3} id="manifestbuilder-addaccessibleresource" toc={true}>`addAccessibleResource`</DocHeading>

**Сигнатура:** `addAccessibleResource(accessibleResource: ManifestAccessibleResource): this`.

Добавляет одно правило [`ManifestAccessibleResource`](#manifestaccessibleresource). Тип описывает пути к ресурсам и аудиторию, которой разрешён доступ. Метод не копирует файлы.

Например, положите изображение в `src/public/images/marker.png`. Сборка скопирует его в `images/marker.png`, а это правило откроет доступ страницам `https://example.com`:

```ts file="../../../../code/api/adnbn/manifest/examples/resources.config.ts" title="adnbn.config.ts"
```

В MV2 Addon Bone выводит общий массив путей: ограничения `matches`, `extensionIds` и `useDynamicUrl` в этот формат не переносятся.

<DocHeading level={3} id="manifestbuilder-getwebaccessibleresources" toc={true}>`getWebAccessibleResources`</DocHeading>

**Сигнатура:** `getWebAccessibleResources(): ManifestAccessibleResource[]`.

**Результат:** массив [`ManifestAccessibleResource`](#manifestaccessibleresource) с нормализованными правилами доступа, ещё до преобразования в формат MV2 или MV3. Метод объединяет явно добавленные правила, `assets` из зависимостей content script и `web_accessible_resources` из `raw`. Без правил возвращает `[]`.

Пути и аудитории очищаются от повторов, совместимые правила объединяются. У URL-шаблонов учитывается origin, а путь приводится к `/*`. Сырая строка ресурса из формата MV2 превращается в правило с `matches: ["<all_urls>"]` и `extensionIds: ["*"]`. Ресурсы content script появляются только после заполнения карты зависимостей.

Следующее чтение учитывает поля, добавленные последующими вызовами [`raw()`](#manifestbuilder-raw).

<DocHeading level={3} id="manifestbuilder-get" toc={true}>`get`</DocHeading>

**Сигнатура:** `get(): T`.

**Результат:** объект манифеста из текущего состояния билдера. Метод синхронно собирает поля, адаптирует их к версии манифеста и браузеру, но сам не записывает файл.

В callback конфигурации ещё нет окончательной карты выходных файлов. Если уже объявлен background или content script, чтение может завершиться ошибкой `Manifest: … not found in dependencies`. Итоговый манифест сборка получает после передачи зависимостей; внутри callback изменяйте билдер и возвращайте дополнительные поля без вызова `get()`.

Ошибку также вызывают пустые зависимости фоновой точки, несколько фоновых JS-файлов для `service_worker`, отсутствие и JS, и CSS у content script, а также конфликт сырой и собранной CSP страниц расширения.

<DocHeading level={3} id="manifestbuilder-raw" toc={true}>`raw`</DocHeading>

**Сигнатура:** `raw(manifest: OptionalManifest): this`.

Добавляет [`OptionalManifest`](#optionalmanifest) с полями в исходном формате: `version_name`, `host_permissions`, `browser_specific_settings` и другими. Версия манифеста в этот контракт не входит.

Объекты объединяются рекурсивно в порядке добавления: позднее скалярное значение заменяет раннее, массивы соединяются. `{}` ничего не добавляет. Это дополнительный источник для генератора: именованные поля билдера могут иметь приоритет, а разрешения и ресурсы проходят свои правила объединения. Например, `setName("Reader")` имеет приоритет над `raw({name: "Other"})` независимо от порядка этих двух вызовов.

Каждый вызов `raw()` обновляет данные для последующего чтения через [`get()`](#manifestbuilder-get) и [`getWebAccessibleResources()`](#manifestbuilder-getwebaccessibleresources). Предварительное чтение не мешает добавить новые поля.

Дополнительное поле можно задать без отдельного метода:

```ts file="../../../../code/api/adnbn/manifest/examples/raw.config.ts" title="adnbn.config.ts"
```

`raw()` возвращает билдер, поэтому не возвращайте результат этого вызова из callback конфигурации. Верните `undefined` либо дополнительный объект манифеста. Для выбора MV2 или MV3 используйте [`manifestVersion`](/api/adnbn/configuration#config-manifestversion).

## `Manifest`

<PropertyBadge text="type" type="info" outline />

Объект WebExtension-манифеста для поддерживаемых браузеров.

```ts file="../../../../code/api/adnbn/manifest/contracts/manifest.ts" title="Manifest"
```

Объединяет внутренние варианты `ChromeManifest`, `FirefoxManifest` и `SafariManifest`. Они основаны на типах `chrome.runtime` и дополняют их браузерными полями, включая `browser_specific_settings`. Имена этих трёх вариантов напрямую из `adnbn` не экспортируются.

Это объединённый TypeScript-контракт; наличие поля в нём не гарантирует поддержку каждым браузером. Формат отдельных полей описан в [справочнике WebExtension-манифеста MDN](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json).

## `ManifestContentScript`

<PropertyBadge text="type" type="info" outline />

Описание content script для манифеста.

```ts file="../../../../code/api/adnbn/manifest/contracts/manifest-content-script.ts" title="ManifestContentScript"
```

Объединяет [`ManifestEntry`](#manifestentry) и `ContentScriptConfig`. `entry` обязателен: по нему сборка выбирает готовые JS и CSS.

`ContentScriptConfig` содержит `matches`, `excludeMatches`, `includeGlobs`, `excludeGlobs`, `allFrames`, `runAt`, `world`, `matchAboutBlank`, `matchOriginAsFallback` и `declarative`. Первые девять полей передают правила запуска; `declarative` относится к сбору разрешений точек входа и самим [`setContentScripts()`](#manifestbuilder-setcontentscripts) не обрабатывается.

У этого алиаса нет фильтров `includeBrowser`, `excludeBrowser`, `mode` и `debug`: он описывает уже выбранную точку сборки. Формат результирующего объекта зависит от MV2 или MV3.

<DocHeading level={3} id="manifestpopup-icon" toc={true}>`icon`</DocHeading>

**Тип:** `string`.

**Тип:** `string`.

Путь к готовому HTML относительно корня расширения. Для Firefox и Opera записывается в `sidebar_action.default_panel`, для остальных целей в MV3 — в `side_panel.default_path`. При отсутствии путь не добавляется; пустая строка сохраняется. Передайте непустой путь для панели с содержимым.

<DocHeading level={3} id="datacollectionpermissions-required" toc={true}>`required`</DocHeading>

**Тип:** ``DataCollectionPermission[] | `${DataCollectionPermission}`[]``.

Категории, необходимые для работы расширения. При отсутствии или пустом списке, с учётом объединения с `raw`, генератор записывает `["none"]`. Строка `"none"` не входит во входной TypeScript-контракт: для отсутствия категорий передайте `[]` или опустите поле. `TechnicalAndInteraction` используйте только в `optional`, согласно контракту Firefox.

<DocHeading level={3} id="datacollectionpermissions-optional" toc={true}>`optional`</DocHeading>

**Тип:** ``DataCollectionPermission[] | `${DataCollectionPermission}`[]``.

Категории, сбор которых пользователь может разрешить дополнительно. При отсутствии, пустом списке или полном пересечении с `required` поле не записывается. Значения перечислены в [`DataCollectionPermission`](#datacollectionpermission).
