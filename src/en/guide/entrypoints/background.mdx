`background` is the backend entrypoint of your browser extension in Addon Bone.

In browser terms, this entrypoint maps to:

- **Manifest V3**: background **service worker**
- **Manifest V2**: background **page** (persistent or non-persistent)

Use background for startup logic, browser event listeners, command handling, messaging orchestration, and privileged extension APIs.

## Quick Start

Create `background.ts` and write your first extension logic directly at the top level.

This is the fastest way to feel how Addon Bone background works: no boilerplate, no extra setup, just a real background module that starts doing useful work immediately.

```ts title="background.ts"
console.log("Background started");

export {};
```

:::warning
Each Entrypoint file is treated as an ES module. If the file does not export Entrypoint options, TypeScript may interpret it as a regular script and show a warning. To explicitly mark the file as a module, add the line `export {}` at the beginning or the end of the file.
:::

## File Structure

Addon Bone auto-discovers background entrypoints by file naming patterns.
Use the default flat structure for most projects. If you have many background files, group them in `backgrounds/`.

<Tabs>
    <Tab label="Default">
        ```tree file="./code/background.default.tree"
        ```
    </Tab>
    <Tab label="Grouped">
        ```tree file="./code/background.group.tree"
        ```
    </Tab>
</Tabs>

Supported patterns include:

- `background.ts`
- `*.background.ts`
- `background/index.ts`
- `*.background/index.ts`
- `backgrounds/background.ts`
- `backgrounds/*.background.ts`
- `backgrounds/background/index.ts`
- `backgrounds/*.background/index.ts`

All discovered background entrypoints are merged into one final background output during build.
You can split logic into multiple files, and Addon Bone will combine them automatically.

## Main Handler

For background entrypoint, the primary handler is `main`.

Default export behavior:

- `export default` **object** -> treated as background definition
- `export default` **function** -> treated as `main`
- named exports are also collected and merged

## Authoring Styles

### 1. Definition helper (`defineBackground`)

```ts
import {defineBackground} from "adnbn";

export default defineBackground({
    permissions: ["storage"],
    hostPermissions: ["*://*.example.com/*"],
    main(options) {
      console.log("Background started", options.permissions);
    }
});
```

### 2. Plain default object

```ts
export default {
    permissions: ["storage"],
    main() {
      console.log("Background started");
    }
};
```

### 3. Named exports + default `main`

```ts title="background.ts"
export const permissions = ["storage"];
export const optionalPermissions = ["tabs"];

export default async function main(options) {
  console.log(options.permissions);
}
```

### 4. Mixed style (named exports + default object)

```ts
export const permissions = ["storage"];

export default {
  permissions: ["tabs"],
  main() {
    console.log("Merged definition");
  }
};
```

If keys overlap, values from the `default` object override named exports.

## Multi-App Structure (`shared` + `apps`)

```tree
src
├── shared
│   └── background.ts
└── apps
    ├── app-a
    │   └── background.ts
    └── app-b
        └── background.ts
adnbn.config.ts
```

### `mergeBackground` behavior

If app background exists:

- `mergeBackground: false` -> use app background only
- `mergeBackground: true` -> combine app + shared backgrounds

If app background does not exist:

- use shared background

Config example:

```ts
import {defineConfig} from "adnbn";

export default defineConfig({
  mergeBackground: true
});
```

## Best Practices

1. Keep each background file self-sufficient: logic and required manifest-affecting options together.
2. Declare required permissions/optional permissions/host permissions in each file that depends on them.
3. Do not rely on another background file to provide required options.
4. This is critical when filters (`includeBrowser`, `excludeApp`, `mode`, `debug`, `manifestVersion`) may exclude files from build output.
